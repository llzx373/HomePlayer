# HomePlayer 播放引擎阶段 4 实施记录

本文记录“统一 GPU 帧、颜色输出与零拷贝”的实际实施状态、验证命令和性能结果。设计契约仍以《播放引擎架构设计》为准；未完成的项目不视为已经支持。

## 重构前基线

- `dotnet test HomePlayer.slnx --configuration Release`：297 项通过，1 项失败。
- 既有的 `Real_media_supports_one_hundred_repeated_seeks_without_demux_fault` 连续两次在约 2 秒处超时；该问题在阶段 4 修改前即可复现，不能记作后续阶段的回归或通过项。
- 现有性能基准仍只覆盖 FFmpeg 软解 BGRA、解码交付观测，不代表 GPU 呈现或真实显示。

## 阶段 1：帧租约契约与验收基线

实施内容：

- 新增与 FFmpeg、DirectShow、Vortice 无关的 `FrameLease` 公共契约，统一时间戳、Session/Epoch/Timeline、颜色、几何、设备代际、零拷贝等级和幂等释放。
- 分离 CPU 平面与 D3D11 纹理资源描述；GPU 描述保留纹理 Subresource、Adapter LUID、共享句柄和同步信息。
- 增加跨线程重复释放、旧 Epoch/Timeline/DeviceGeneration 丢弃测试。
- 增加可选微基准，测量租约分配与释放吞吐和托管分配量；不把该微基准当作播放性能结论。

验证命令：

```powershell
dotnet test tests/HomePlayer.Core.Tests/HomePlayer.Core.Tests.csproj --configuration Release
$env:HOMEPLAYER_PERF_FRAME_LEASE_OUTPUT="$PWD/artifacts/performance/frame-lease-stage1.json"
dotnet test tests/HomePlayer.Core.Tests/HomePlayer.Core.Tests.csproj --configuration Release --filter "FullyQualifiedName~FrameLeasePerformanceTests"
```

验证结果：Core 221 项通过。当前机器上 20 万次租约分配与释放共分配 44,800,000 字节，即每次 224 字节，20 万个租约均只释放一次；该结果只作为后续同机回归基线，不设跨硬件吞吐排名。

状态：契约和测试已实现，现有 BGRA 播放路径在阶段 2 才接入，当前不得据此声明已经支持 GPU 帧。

## 阶段 2：现有 BGRA 路径接入 FrameLease

实施内容：

- `VideoFrame` 改为继承 `CpuFrameLease`，公共时间线、颜色、设备代际和幂等释放统一由基类实现。
- 保留 `Stride`、`Data`、`BottomUp` 和 `ReturnBuffer` 等既有调用契约；旧帧默认仍为 BGRA、Z1。
- 不修改 FFmpeg swscale、LAV BGRA Sink、Presenter 上传和截图路径，因此本阶段不产生新的画质或零拷贝能力。

验证与性能：

- Core 222 项测试通过，新增旧 `VideoFrame` 的 CPU 租约兼容性测试。
- 使用同一 `baseline-1080p30-h264-aac.mp4` 完成 30 次打开、100 次目标帧 seek 和 5 秒稳态测试，失败均为 0。
- `Compare-Playback.ps1` 验收通过：首帧 P95/P99、seek P95/P99 均未回退；稳态托管分配由 595,224 增至 606,024 字节（+1.81%，低于 30% 回归预算）， decoded frames 均为 150。
- 结果文件为 `artifacts/performance/playback-stage2.json` 和 `playback-stage2-comparison.json`；延迟差值属于同机单次 A/B 观测，不据此宣称性能提升。

状态：BGRA 已完成公共租约适配，默认播放行为保持不变。
