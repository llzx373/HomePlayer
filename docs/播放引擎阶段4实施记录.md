# HomePlayer 播放引擎阶段 4 实施记录

本文记录“统一 GPU 帧、颜色输出与零拷贝”的实际实施状态、验证命令和性能结果。设计契约仍以《播放引擎架构设计》为准；未完成的项目不视为已经支持。

## 重构前基线

- `dotnet test HomePlayer.slnx --configuration Release`：297 项通过，1 项失败。
- 既有的 `Real_media_supports_one_hundred_repeated_seeks_without_demux_fault` 连续两次在约 2 秒处超时；该问题在阶段 4 修改前即可复现，不能记作后续阶段的回归或通过项。
- 现有性能基准仍只覆盖 FFmpeg 软解 BGRA、解码交付观测，不代表 GPU 呈现或真实显示。

## 阶段 1：帧租约契约与验收基线

实施内容：

- 新增与 FFmpeg、DirectShow、Vortice 无关的 `FrameLease` 公共契约，统一时间戳、Session/Epoch/Timeline、颜色、几何、设备代际、零拷贝等级和幂等释放。
- 分离 CPU 平面与 D3D11 纹理资源描述；GPU 描述保留纹理 Subresource、Adapter LUID、共享句柄和同步信息。
- 增加跨线程重复释放、旧 Epoch/Timeline/DeviceGeneration 丢弃测试。
- 增加可选微基准，测量租约分配与释放吞吐和托管分配量；不把该微基准当作播放性能结论。

验证命令：

```powershell
dotnet test tests/HomePlayer.Core.Tests/HomePlayer.Core.Tests.csproj --configuration Release
$env:HOMEPLAYER_PERF_FRAME_LEASE_OUTPUT="$PWD/artifacts/performance/frame-lease-stage1.json"
dotnet test tests/HomePlayer.Core.Tests/HomePlayer.Core.Tests.csproj --configuration Release --filter "FullyQualifiedName~FrameLeasePerformanceTests"
```

验证结果：Core 221 项通过。当前机器上 20 万次租约分配与释放共分配 44,800,000 字节，即每次 224 字节，20 万个租约均只释放一次；该结果只作为后续同机回归基线，不设跨硬件吞吐排名。

状态：契约和测试已实现，现有 BGRA 播放路径在阶段 2 才接入，当前不得据此声明已经支持 GPU 帧。

## 阶段 2：现有 BGRA 路径接入 FrameLease

实施内容：

- `VideoFrame` 改为继承 `CpuFrameLease`，公共时间线、颜色、设备代际和幂等释放统一由基类实现。
- 保留 `Stride`、`Data`、`BottomUp` 和 `ReturnBuffer` 等既有调用契约；旧帧默认仍为 BGRA、Z1。
- 不修改 FFmpeg swscale、LAV BGRA Sink、Presenter 上传和截图路径，因此本阶段不产生新的画质或零拷贝能力。

验证与性能：

- Core 222 项测试通过，新增旧 `VideoFrame` 的 CPU 租约兼容性测试。
- 使用同一 `baseline-1080p30-h264-aac.mp4` 完成 30 次打开、100 次目标帧 seek 和 5 秒稳态测试，失败均为 0。
- `Compare-Playback.ps1` 验收通过：首帧 P95/P99、seek P95/P99 均未回退；稳态托管分配由 595,224 增至 606,024 字节（+1.81%，低于 30% 回归预算）， decoded frames 均为 150。
- 结果文件为 `artifacts/performance/playback-stage2.json` 和 `playback-stage2-comparison.json`；延迟差值属于同机单次 A/B 观测，不据此宣称性能提升。

状态：BGRA 已完成公共租约适配，默认播放行为保持不变。

## 阶段 3：Presenter 支持多类帧输入

实施内容：

- 播放引擎、会话、控制器、遥测和页面的帧事件统一为 `FrameLease`；BGRA 仍由兼容的 `VideoFrame` 生产。
- Presenter 分离 BGRA、CPU NV12/P010 和 D3D11 纹理输入。CPU YUV 使用独立亮度/色度动态纹理，GPU 输入直接创建 SRV，不经过 CPU 回读。
- D3D11 输入校验 DeviceGeneration、Adapter LUID、纹理尺寸、格式和 Array Subresource；设备重建使旧代际帧失效。
- 新增 CPU 平面 Offset/Stride/行长/行数边界校验，异常数据在 Map 和拷贝前被拒绝。
- 暂时只保留旧 BGRA 内存截图；YUV/GPU 最终显示帧截图尚未完成，不声明这些路径已具备截图能力。

验证与性能：

- App Release 构建零警告、零错误；Core 223、Playback 27、Library 53 项有效测试通过。既有的 100 次 seek 基线失败未计入通过项。
- 同媒体 30 次打开、100 次目标帧 seek 和 5 秒稳态测试失败均为 0。相对阶段 2，首帧 P95 变化 +3.00%，seek P99 +4.33%，均在预算内；稳态分配均为 606,024 字节。
- 结果文件为 `artifacts/performance/playback-stage3.json` 和 `playback-stage3-comparison.json`。
- 使用隔离数据目录启动真实 App 并打开同一媒体，进程保持响应且持续播放，无崩溃或 Presenter 错误日志。当前未执行视觉截图验收，GPU 输入也尚无实际硬解生产者，不能据此声明 Z2/Z3 已验收。

状态：多格式输入基础已完成，默认 BGRA 路线保持可用；下一阶段接入 Native 软解 YUV 生产者。

## 阶段 4：Native 软解 YUV 直传（Z2）

实施内容：

- FFmpeg 默认对 NV12、P010、yuv420p、yuv420p10le 交付 CPU YUV 租约；yuv420p 在复制时交织 U/V，10bit 低位样本转换为 P010 高位对齐。其他格式继续走 swscale BGRA。
- `EnableDirectYuv=false` 可强制旧 BGRA 路径，用于同版本 A/B 和故障回退；PipelineInfo 按实际帧报告 bgra/nv12/p010 和 Z1/Z2。
- Basic Renderer 使用随帧常量处理 BT.601/BT.709/BT.2020 和 Full/Limited。Unknown 矩阵保留 swscale 的 BT.601 默认，不按分辨率猜测并改变旧画质。
- YUV 平面描述按格式和尺寸复用，像素数据继续使用池化缓冲。CPU YUV 截图只在用户请求时转换为 BGRA，正常播放不保留 RGB 副本。
- 性能工具支持同构建 BGRA/Z2 测试并记录实际路径；对比脚本只有显式指定 `-AllowDifferentQuality` 才比较不同质量路径，报告写入 `qualityEquivalent=false`。

验证与性能：

- 真实 1080p H.264 媒体验证 NV12、Z2、平面边界、PipelineInfo 和 BGRA 回退。使用与 D3D 一致的双线性色度参考，BGRA/YUV 平均绝对通道误差为 1.711（容差 8）。Unknown 矩阵若误用 BT.709，误差为 9.31，已据此修正为兼容默认。
- 使用构建时生成的 64×48、10bit HEVC 样本验证 P010、Z2、两个平面的 16bit 行长和按需 BGRA 截图转换；大型媒体不提交到仓库。
- 同构建强制 BGRA 与默认 Z2 分别完成 30 次打开、100 次目标帧 seek 和 5 秒稳态测试，失败均为 0。Z2 相对 BGRA：首帧 P95 +0.05%，seek P95 -2.69%，seek P99 +3.96%，稳态分配 -6.13%；均在预算内。
- 两组稳态 CPU 利用率基本相同（0.5371%/0.5372% 全机归一化），不据此宣称 CPU 性能提升。结果文件为 `playback-stage4-bgra.json`、`playback-stage4-z2.json` 及各自 comparison。
- 强制 BGRA 相对阶段 3 的同质量回归也通过，说明回退路径未因新生产者被破坏。
- App Release 构建零警告、零错误；Core 231、Playback 29、Library 53 项有效测试通过。默认 Z2 的真实 App 播放冒烟保持响应，无 Presenter 错误日志；当前仍未做视觉截图验收。

状态：Native NV12/P010 Z2 已接入并通过真实媒体验证，BGRA 回退保持可用；实际渲染器呈现性能仍需后续硬件验收。

## 阶段 5：Native D3D11VA 最小零拷贝路径（Z3）

实施内容：

- Presenter 通过 `D3D11SharedDevice` 向 Native Provider 提供设备、immediate context、Adapter LUID、DeviceGeneration 和共享锁；FFmpeg 与渲染线程使用同一同步对象。
- 使用外部 D3D11 device/context、`get_format`、`avcodec_get_hw_frames_parameters` 和 `av_hwframe_ctx_init` 协商硬解；打开失败重建软件解码器，保留 Z2/BGRA 回退。
- 解码纹理同时声明 Decoder 和 ShaderResource。GPU 租约持有 AVFrame 引用，Presenter 直接创建 NV12/P010 SRV，不做逐帧 CPU 回读或上传。
- 支持硬件对齐纹理大于可见尺寸，使用 UV 缩放裁掉 1088→1080 等填充区域；GPU 帧队列按估算显存字节计入有界预算。
- 增加真实 D3D11 设备集成测试，强制要求首帧为 Z3、LUID 一致、纹理尺寸/格式/BindFlags 合法且可实际创建 SRV；无设备环境继续走软件测试。

验证与性能：

- 真实设备测试最初发现外层 `AVHWDeviceContext.hwctx` 指针误用和缺少 ShaderResource BindFlags，均已修正；最终硬解首帧和 SRV 验证通过。
- App Release 构建零警告、零错误；Core 232、Playback 30、Library 53 项有效测试通过。
- 两轮 D3D11VA 均完成 30 次打开、100 次目标帧 seek 和 5 秒稳态测试，失败为 0，实际输出均为 NV12/Z3。
- 第二轮首帧 P95 为 27.59 ms，seek P95 为 375.83 ms，稳态 process CPU 为 46.875 ms；Z2 对照分别为 29.27 ms、134.40 ms、859.375 ms。硬解显著降低稳态 CPU，但随机 seek 明显更慢。
- 软件 200 ms seek Profile 的首次对比失败已保留。新增独立 `PlaybackPerformanceProfile.D3D11.json`，seek 绝对上限为 500 ms；首次 Z3 只验收绝对预算并建立基线，报告明确写有 `PassedAbsoluteBudgetsOnly; regression baseline not evaluated`，不声称通过跨路线回归。
- 结果文件为 `playback-stage5-z3.json`、`playback-stage5-z3-repeat.json` 和 `playback-stage5-z3-comparison.json`。这些指标仍是 Decoded/TargetDecodedFrame 观测，不是实际显示时间。
- 默认 App 播放冒烟保持响应，无 Presenter 错误日志；当前未做视觉截图验收，下一阶段继续检查资源回收和设备代际。

状态：Native 同设备 Z3 最小路径已通过真实硬件验证；默认策略必须在后续长稳、设备恢复和真实呈现验收中考虑 seek 与 CPU 的权衡。
