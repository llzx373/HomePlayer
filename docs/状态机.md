# HomePlayer 状态机与不变式

本文把散落在播放、媒体库、字幕和 AI 子系统里的显式枚举与隐式字段统一记录下来，用于回答三个问题：

1. 这个子系统到底有哪些状态、允许哪些转换；
2. 哪些状态/转换在代码里实际可达，但违反设计或不变式；
3. 每个已确认缺陷对应哪条回归测试。

记录时间：2026-11-07（版本 0.3.0-19）。行号会随代码变化，定位以“文件 + 成员”名称为准。

## SM-1 播放会话（PlaybackSession）

### 状态

三个维度独立变化：

- `PlaybackLifecycle`：`Closed`、`Opening`、`Ready`、`Closing`、`Failed`
- `PlaybackTransportState`：`Stopped`、`Playing`、`Paused`、`Ended`
- `PlaybackOperation`：`None`、`Seeking`、`Recovering`、`TrackChanging`

另有 `Epoch`、`SurfaceGeneration`、`DeviceGeneration` 三个隔离/代次计数。

### 不变式

- **I1 生命周期单向**：创建即为 `Ready`（会话由 Provider 打开成功后才创建）；`Closing → Closed` 单向；`Failed` 是终态，只能再进入 `Closing/Closed`，不得回到 `Ready`。
- **I2 关闭幂等**：重复 `Dispose()` 只释放一次内部引擎。
- **I3 失败后不再执行控制命令**：`Failed` 或 `Closed` 后只接受 `Stop`、`Close`；`Stop` 必须幂等且不触碰可能已释放的引擎。
- **I4 帧代次隔离**：`Frame.Epoch != Epoch` 的帧必须归还缓冲区，不得下发。
- **I5 Seek 原子性**：`Seek` 先递增 `Epoch`，再调用引擎；`CurrentOperation` 在 `finally` 中回到 `None`。
- **I6 命令结果三态**：每个命令先发 `Accepted`，最终必须发 `Completed` / `Cancelled` / `Failed` 之一。

### 转换表

| 当前 | 事件 | 条件 | 下一状态 | 副作用 |
| --- | --- | --- | --- | --- |
| 创建 | Provider 打开成功 | — | Lifecycle=Ready, Transport=Stopped | 订阅帧/结束/故障事件 |
| Ready/Playing | Play | — | Transport=Playing | `InnerEngine.Play()` |
| Ready/Paused/Playing | Pause | — | Transport=Paused | `InnerEngine.Pause()` |
| 任意可用 | Seek | — | Operation=Seeking → None | `Epoch++`，引擎 seek |
| Playing | 引擎 Ended | 未关闭 | Transport=Ended | 抛 `Ended` |
| 任意未关闭 | 内部故障 | — | Lifecycle=Failed | 抛 `Faulted`，拒绝后续控制命令 |
| Failed/Closed | Stop | — | Transport=Stopped | 仅记录状态，不调用引擎 |
| 任意 | Close | 未关闭 | Closing → Closed | 取消订阅、释放引擎 |
| Closed | Close/Stop | — | Closed | 幂等，返回 Completed |
| Closed/Failed | Play/Pause/Seek | — | 不变 | 返回 Failed（`"播放会话已失败/关闭。"`） |

### 代码中不可达的状态

- `PlaybackLifecycle.Opening` 从未赋值（Provider 先 `Open` 成功再构造会话）。
- `PlaybackOperation.Recovering`、`TrackChanging` 从未赋值，恢复由控制器重开会话完成。
- `SurfaceGeneration` / `DeviceGeneration` 只有 `NotifySurfaceChanged/NotifyDeviceChanged` 显式调用，普通播放路径不会变化。

这些不是缺陷，但读快照的人不应把它们当作已实现的分维状态。

## SM-2 播放控制器编排（PlaybackController）

控制器没有单一枚举，状态由以下字段共同编码：

- `_engine`：当前引擎或 `null`
- `_playingPath`：已成功打开并正在播放的路径（打开中为 `null`）
- `_token`：打开/停止代次；任何异步完成都要回比
- `_autoPlaySuppressed`：暂停或关闭窗口后禁止自动开播/连播
- `_recoveryPath` / `_recoveryAttempts`：同一文件自动恢复预算
- `_rate` / `_volume` / `_muted` / `AudioDelayMs`：跨重开保留的用户意图
- `Status` 字符串：`就绪`、`正在打开`、`正在播放`、`已暂停`、`播放结束`、`播放已恢复`、`无法播放`、`播放失败：…` 等

### 不变式

- **C1 最新打开胜出**：`PlayCurrentAsync` 先 `++_token`；旧打开完成时若 token 不匹配，只丢弃引擎，不改变当前状态。
- **C2 单引擎**：新引擎打开前先 `_engine = null` 并异步释放旧引擎；`PendingDispose()` 保证上一份引擎退出后才开新文件。
- **C3 自动播放抑制**：`Pause()` 置 `_autoPlaySuppressed = true`；打开完成回调不得自动 `Play()`，`OnEnded` 不得自动连播。
- **C4 同文件恢复有上限**：`_recoveryAttempts` 只在切换文件时清零，同一文件最多 `MaxRecoveryAttempts = 2` 次恢复。
- **C5 恢复/失败不得换集**：只有普通“打开新条目失败”才允许 `NextIndex`；恢复、路线切换、音频设备回退必须停留在当前条目。
- **C6 用户播放意图跨重开保留**：音量、静音、倍速、音频延迟不应因恢复或路线切换被重置。
- **C7 事件顺序**：`SeekStarted` 只在确实发生 seek 时触发；`Stopped` 只在显式停止/关闭时触发。

### 主要转换

| 当前 | 事件 | 下一状态 | 说明 |
| --- | --- | --- | --- |
| 未播放 | `PlayPathsAsync(paths, i)` | 正在打开 | 记住旧进度，替换播放列表 |
| 正在打开 | `Pause()` | 打开中 + 抑制自动播放 | 引擎打开后进入 `已暂停` |
| 正在打开 | `Stop()`/`ShutdownAsync()` | 已停止 | `_token++`，旧打开结果被丢弃 |
| 正在播放 | 引擎 Faulted | 恢复中 | `OnFaulted` → `TryRecoverFromFault` |
| 正在播放 | 音频输出失败 | 回退默认设备 | 重开当前条目，失败时不得换集 |
| 正在播放 | Ended | 下一集 / 播放结束 / 单集重播 | 受 `AutoAdvance`、`Repeat`、抑制状态影响 |
| 任意 | 文件变化/删除 | 进度失效 | `ForgetProgress(path)`，下次不续播 |

### 可达的非法转换（已修复）

1. **音频回退失败换集**：`OnAudioOutputFailed` 原先把重开当作普通打开，失败后会执行 `Playlist.NextIndex(false)`，当前视频被跳过。见下方 Issue #1。
2. **恢复/路线切换丢倍速**：`PlayCurrentAsync` 无条件 `_rate = 1.0`，而 `PlaybackTransferState.PlaybackRate` 从未应用。见 Issue #3。
3. **无操作音轨切换触发 seek**：`SetAudioTrack` 不比较当前索引就触发 `SeekStarted`，导致清帧并重启实时字幕。见 Issue #4。

## SM-3 手动路线切换

### 状态

`PlaybackRouteTransitionPhase`：`Preparing → Committed | Aborted`，由 `_routeOperationId` 保证只有最新操作能落盘。

### 不变式

- 每次 `SwitchRouteAsync` 递增 `_routeOperationId`；旧操作延迟完成时 `CompleteRouteSwitch` 直接返回。
- `Preparing` 只对应一个 `RouteSwitchOperation`；`Committed/Aborted` 后 `_activeRouteSwitch` 必须为 `null`。
- 失败保留 `_failedRouteTransition` 供 `RetryRouteSwitchAsync` 使用，但仅当播放列表仍停在同一个 `MediaId`。
- 转移状态（位置、播放中、音量、静音、倍速、音频延迟/轨道）必须在重开时继续生效。

### 转换表

| 当前 | 事件 | 下一状态 | 条件 |
| --- | --- | --- | --- |
| 空闲 | `SwitchRouteAsync(route)` | Preparing | `route != Auto` 且有当前条目 |
| Preparing | 新路线打开成功 | Committed | 操作号仍是最新 |
| Preparing | 打开失败 | Aborted | 操作号仍是最新；记录可重试 |
| Preparing | 新切换/停止/普通打开 | Aborted（旧操作） | `_routeOperationId` 已变化 |
| Aborted | `RetryRouteSwitchAsync` | Preparing | 当前条目仍是失败操作的 `MediaId` |
| Committed/Aborted | `InvalidateRouteSwitch` | 空闲 | 清理失败记录 |

## SM-4 解码损坏恢复

`MediaDecodeRecoveryPolicy`：`consecutive` 连续错误计数 + `Total` 累计 + `LastError`。

- 不变式：`TryRecover` 返回 `consecutive <= Limit`；任一成功解码调用 `Reset()` 只清零连续计数；`ResetAll()` 在打开新媒体时清零全部证据。
- 超限后抛 `InvalidOperationException`，引擎通过 `Faulted` 上报，由控制器 SM-2 接管。
- 视频/音频各一份策略，互不影响。

转换：`Healthy --错误--> Recovering --成功--> Healthy`；`Recovering --连续错误超过 Limit--> Faulted`。

## SM-5 媒体库扫描

### 状态

`LibraryScanStage`：`Idle`、`Scanning`、`Processing`、`Complete`、`Incomplete`、`Unavailable`。

### 不变式

- 完整扫描结束且没有待处理项：`Complete`；有待处理项：`Processing`。
- 任一目录读取失败：`Incomplete`，保留未确认条目，不执行删除。
- 根目录不存在：`Unavailable`，保留条目与进度。
- 只有 `Unavailable` 会被 `AvailabilityWorkerAsync` 每 5 秒自动重试；`Incomplete` 依赖文件系统事件或手动刷新。

### 转换表

| 当前 | 事件 | 下一状态 | 备注 |
| --- | --- | --- | --- |
| Idle | `Refresh/Reconcile` | Scanning | 枚举文件 |
| Scanning | 扫描完整、无 pending | Complete | 删除未确认条目、重建目录表 |
| Scanning | 扫描完整、有 pending | Processing | 后台 worker 处理元数据/封面 |
| Processing | 最后一项完成 | Complete | `PendingCount == 0` |
| Scanning/Processing | 目录不可读 | Incomplete | 记录警告，保留条目 |
| 任意 | 根目录消失 | Unavailable | 可用性 worker 轮询恢复 |
| Unavailable | 根目录恢复 | Scanning | `Watch + ReconcileInBackground` |

## SM-6 媒体条目与工作项

- `ItemStatus`：`Pending → Ready | Failed`；文件变化/手动重排会回到 `Pending`。
- `MatchStatus`：`None → Matched | NeedsReview | Failed`。
- `WorkItem.State`：`0` 排队、`1` 处理中、`2` 完成（删除工作项）、`3` 失败；`PendingCount` 统计 `0/1`。
- 不变式：工作项完成时删除；失败仍保留状态但不计入 pending；删除媒体库/条目的同时删除工作项、进度和偏好。

并发点：`Submit` 用 `_pending/_inFlight/_resubmit` 防止同一项并发处理；处理中再次提交会记录一次补跑。

## SM-7 字幕选择（SubtitleSession）

`Choice`：`Off`、`Auto`、`Sidecar`、`Embedded`、`Live`。

### 不变式

- `Sidecar` ⇒ `_sidecar != null`；`Embedded` ⇒ `_embedded >= 0`（在轨道列表未知时允许暂时为 `-1`，由 `SetEmbeddedList` 解析或回退 `Auto`）。
- `Off` 时 `CueAt` 永远返回 `null`。
- `Remember()` 只记录非 `Off` 的选择；`Off()` 先记录再关闭，`Toggle()` 从 `Off` 恢复上次选择。
- 损坏/空字幕进入 `_unreadable`，`Auto` 不得选中它。

可疑点：`UseLive()` 不调用 `Remember()`，所以“实时字幕 → 关闭 → 再打开”会回到 `Auto` 而不是 `Live`。当前按“实时字幕是临时会话”理解，未修改。

## SM-8 实时字幕分段（LiveSubtitleBuffer）

每个 `SegmentId` 有 `Final=false/true` 两态。

- 不变式：已 `Final` 的分段不得被非 final 更新降级；相同内容的重复更新返回 `false`。
- 空更新会删除分段；`Final=true` 的空更新可以删除已有分段（用于识别器撤回）。
- `_provisional` 用引用相等标记未定稿 cue；`Invalidate` 时整体重建。
- 调用方（`PlayerPage`）保证只在 UI 线程调用。

## SM-9 实时翻译启动（LiveTranslationService）

隐式状态：`未启动 → 启动中 → 就绪 | 失败 | 已释放`。

### 不变式

- 同一服务实例同时只允许一个启动任务。
- 启动失败/取消后必须允许再次 `StartAsync`，否则一次瞬时网络或模型错误会让该实例永久不可用。
- 启动失败必须回收半启动的 worker 进程，避免下一次重试复用已退出的管道。

### 转换表

| 当前 | 事件 | 下一状态 | 备注 |
| --- | --- | --- | --- |
| 未启动 | `StartAsync` | 启动中 | 缓存 Task |
| 启动中 | 模型/worker 就绪 | 就绪 | 后续 `TranslateAsync` 可写入 |
| 启动中 | 失败/取消 | 失败 | 必须清除缓存 Task，允许重试 |
| 已释放 | `StartAsync` | 失败 | `_disposed` 检查抛 `OperationCanceledException` |

## SM-10 悬停预览请求

隐式状态：`未悬停 → 计时中 → 截取中 → 显示 | 暂无预览`，由 `_seekPreviewRequest` 代次和 `_seekPreviewCancellation` 管理。

- 不变式：旧请求完成后必须用 `IsSeekPreviewCurrent(request, path, target)` 回比，旧结果不得覆盖新悬停位置。
- `HideSeekPreview` 递增代次并取消当前请求。
- **待观察**：`SeekPreviewService.Dispose` 用普通 `bool _disposed`，`CaptureAsync` 在 `await Task.Run(MediaKey)` 之后才访问 `_shutdown.Token`，存在“检查已释放 → Dispose 释放 CTS → 访问 Token”的竞态，可能抛 `ObjectDisposedException`。UI 目前会吞掉异常并显示“暂无预览”，因此未按高优先级修复。

## SM-11 渲染门

`RendererGate.Decide(int state, bool flushing, long streamTime)` 的三态：`Stopped=0`、`Paused=1`、`Running=2`。

- `flushing` 或 `Stopped` → `false`（不得提交）
- `Paused` → `null`（等待，不判定）
- `Running && streamTime <= 0` → `true`（立即提交首帧）
- 其它 → `null`

未知整数状态一律 `false`，即失败关闭。

---

## SM-12 应用退出 / 托盘

`AppExit.Plan(closeToTray, exiting)` 产出 `HideToTray`、`BeginExit`、`AllowClose`。

- `CloseToTray=true && !exiting` → 关闭窗口只隐藏到托盘。
- `exiting=true` → 允许真正关闭；`AppHost.Exiting` 是幂等闩锁。
- 退出有看门狗：`ArmExitWatchdog` 超时后记录线程快照并强杀进程。
- 隐藏/最小化会 `Pause()` 并暂停渲染；恢复可见时再恢复渲染。

## 已确认缺陷、优先级与修复

优先级按用户可见影响排序：错误内容/错误条目 > 状态永久卡死 > 用户意图丢失 > 事件噪音。

| 优先级 | 问题 | 影响 | 状态 | 回归测试 |
| --- | --- | --- | --- | --- |
| P1 | 音频设备回退重开失败会跳到下一集 | 播放错误视频、当前条目进度/意图丢失 | 已修复 | `Audio_fallback_failure_does_not_advance_to_the_next_playlist_item` |
| P1 | 会话故障后没有 `Failed`，仍执行控制命令；关闭后 `Stop` 不幂等 | 故障会话可能继续操作已释放引擎；快照谎报 `Ready` | 已修复 | `Inner_fault_marks_the_session_failed_and_rejects_further_play`、`Stop_after_close_is_idempotent_even_when_the_engine_rejects_it` |
| P2 | 恢复/路线切换把倍速重置为 1.0 | 用户设置的倍速在自动恢复或切换路线后丢失 | 已修复 | `Recovery_preserves_the_current_playback_rate`、`Route_switch_preserves_the_current_playback_rate` |
| P2 | 实时翻译启动失败被永久缓存，CPU worker 启动失败不回收 | 一次瞬时失败后本实例无法重试；可能泄漏进程 | 已修复 | `Failed_start_can_be_retried_instead_of_returning_the_cached_fault` |
| P3 | 重复选择当前音轨也触发 `SeekStarted` | 清空当前帧、重启实时字幕，产生无意义闪断 | 已修复 | `Repeating_the_same_audio_track_does_not_raise_seek_started` |

### Issue #1 音频回退失败不得换集

**证据（修复前）**：`OnAudioOutputFailed` 调用 `PlayCurrentAsync(route)`，`recovery=false` 且没有路线操作；打开异常分支执行 `Playlist.NextIndex(false)`，于是设备回退失败后直接打开下一集。

**修复**：`PlayCurrentAsync` 增加 `advanceOnFailure` 参数；音频回退传 `false`，失败时停在当前条目并进入 `无法播放`。

### Issue #2 会话故障状态与命令门禁

**证据（修复前）**：`PlaybackSession` 只在构造时把 `_lifecycle` 设为 `Ready`，内部 `Faulted` 仅转发事件，从不改成 `Failed`；`ExecuteAsync` 只拦截 `_closed`，故障会话仍会执行 `Play/Pause/Seek`。`Stop` 在关闭后仍调用内部引擎，真实引擎可能抛 `ObjectDisposedException` 并被记成 `Failed`。

**修复**：订阅内部故障并置 `Failed`；`Failed/Closed` 只接受 `Stop/Close`；`Stop` 在不可用状态下幂等返回 `Completed`；`Dispose` 在锁内完成 `Closing → Closed`。

### Issue #3 恢复/路线切换保留倍速

**证据（修复前）**：`PlaybackTransferState` 已包含 `PlaybackRate`，`SwitchRouteAsync` 也采集了它，但 `PlayCurrentAsync` 无条件 `_rate = 1.0`，从未读取 `routeSwitch.Transfer`。

**修复**：`RouteSwitchOperation` 持有 `Transfer`；路线切换用转移倍速，自动恢复沿用当前 `_rate`，只有真正换集才重置为 1.0。

### Issue #4 无操作音轨切换不触发 seek

**证据（修复前）**：`SetAudioTrack` 无论索引是否变化都触发 `SeekStarted`；`PlayerPage` 在该事件里清帧并重启实时字幕。

**修复**：先比较 `_engine.AudioTrackIndex`，相同则直接返回。

### Issue #5 实时翻译启动可重试

**证据（修复前）**：`StartAsync` 用 `_start ??=` 缓存启动任务；失败任务永远留在字段里，下一次调用返回同一个异常。CPU 启动路径失败时也没有 `StopWorker()`。

**修复**：启动缓存加锁，`Faulted/Canceled` 时重新启动；CPU 启动失败回收 worker。

## 已发现但未修复 / 需要产品决策

这些不是本次确认的高影响缺陷，保留证据供后续处理：

1. **SeekPreviewService 释放竞态**：`CaptureAsync` 在异步 `MediaKey` 后访问 `_shutdown.Token`，`Dispose` 可能已释放 CTS。调用方吞异常，表现为“暂无预览”。
2. **Incomplete 扫描不自动重试**：`AvailabilityWorkerAsync` 只处理 `Unavailable`；权限恢复或网络共享短暂失败后，`Incomplete` 会停留到下一次文件事件/手动刷新。
3. **`PlaybackLifecycle.Opening` 与 `PlaybackOperation.Recovering/TrackChanging` 不可达**：快照字段存在但永不出现，容易误读为已实现。
4. **`SubtitleSession.UseLive` 不记录恢复点**：`Live → Off → Toggle` 回到 `Auto`；如果产品希望恢复实时字幕，需要补 `Remember()` 并处理实时会话不可重建的情况。
5. **`_token`、`_rate` 等字段跨线程读写未使用 `Volatile/Interlocked`**：当前由 UI 线程串行化调用，控制器内部异步回调只读比较；若未来允许后台线程直接调用，需要加强内存序。
6. **`Playlist.PreviousIndex` 在随机播放游标为 0 时返回当前索引**：效果是“重开当前条目”，与“上一首”语义不完全一致。
