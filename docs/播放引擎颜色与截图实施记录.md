# HomePlayer 播放引擎颜色与截图实施记录

本文记录“颜色、HDR 与截图收尾”的逐条目实施状态。设计契约仍以《播放引擎架构设计》为准；每项独立提交，真实显示器和视觉矩阵没有证据时不写成已通过。

## 条目 1：源 HDR10 mastering 与 content-light 元数据

实施内容：

- `VideoColorMetadata` 增加可空 `VideoHdr10Metadata`，Native 的 BGRA、CPU YUV 和 D3D11 帧都保留 FFmpeg side data 中的 mastering display 与 content light 信息。
- 色域坐标按 DXGI 的 0.00002 单位换算，mastering 最小亮度按 0.0001 nit 换算；使用四舍五入避免有理数浮点截断。缺少 side data 或其中可选字段时，只回退对应字段到既有 BT.2020、1000/400 nits 值。
- HDR 交换链不再固定写入回退值，而是使用当前帧的来源元数据。来源变化时更新 `SetHDRMetaData`，相同来源不重复写入；无来源信息时行为与阶段 4 一致。

验证：

- 测试时生成真实 HEVC Main10 HDR10 媒体，显式包含 BT.2020 色域、1000/0.005 nits mastering 范围、MaxCLL 1200 和 MaxFALL 500。
- 解码帧的全部色域坐标、mastering 和 content-light 字段逐项通过断言；`dotnet test HomePlayer.slnx --configuration Release` 为 Core 246、Playback 57、Library 53，全部通过。
- `dotnet build src/HomePlayer.App/HomePlayer.App.csproj --configuration Release`：0 警告、0 错误。

边界：

- 当前完成的是静态 HDR10 元数据保留和输出，不代表 HDR10+、Dolby Vision 动态元数据、色调映射算法或真实 HDR 显示器视觉效果已经验收。
- LAV/DirectShow 帧没有 FFmpeg side data 来源，继续使用回退值；其源元数据路径需要单独实现。
- 真实 HDR 输出、系统 HDR 切换和多屏 SDR/HDR 跨屏仍留待硬件矩阵。

状态：Native 源 HDR10 元数据保留与交换链输出已完成，后续继续 GPU 最终显示帧 Staging 截图。

## 条目 2：GPU 最终显示帧 Staging 截图

实施内容：

- D3D11 输入的截图在渲染线程取得实际交换链后备缓冲，通过 `CopyResource` 复制到 CPU 可读的 Staging Texture；不再返回不支持或用源纹理冒充最终显示帧。
- SDR `B8G8R8A8_UNorm` 按行回读为 BGRA。HDR `R16G16B16A16_Float` 只在用户截图时执行 PQ 解码、Reinhard 映射、BT.2020→BT.709 和 SDR 编码，输出可保存的 SDR BGRA；正常播放不保留 CPU 副本。
- 回读在设备同步锁和渲染线程内执行，UI 等待上限为 2 秒，失败或超时返回 false 并记录诊断，不无限等待渲染线程。
- CPU BGRA/YUV 继续沿用既有源帧截图路径；WinUI 字幕是否包含仍由现有截图设置和叠层合成决定，不把控件混入后备缓冲。

验证：

- 使用真实 D3D11 设备分别构造 SDR 与 HDR 纹理并执行 Staging 回读。SDR 尺寸、Stride 和全部像素字节一致；HDR 黑位、亮部 SDR 转换和 Alpha 均通过。
- `dotnet test HomePlayer.slnx --configuration Release`：Core 246、Playback 59、Library 53，全部通过。
- `dotnet build src/HomePlayer.App/HomePlayer.App.csproj --configuration Release`：0 警告、0 错误。

边界：

- 测试直接验证后备缓冲到 BGRA 的数据路径，不等同于真实 HDR 显示器的视觉截图验收，也不表示 Windows 合成器中的 WinUI 控件被包含。
- HDR 输出得到的是面向 PNG 的色调映射 SDR 截图，不是原始 PQ/FP16 文件；原始 HDR 截图格式尚未提供。

状态：GPU 最终显示帧 Staging 截图已完成，后续继续路线事务与稳定轨道身份。
