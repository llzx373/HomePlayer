# 自定义渲染规则与 Shader

状态：已实现并完成 Core、Playback 和真实应用端到端验证。后续新增渲染需求先登记到 `docs/路线图.md` 的“自定义渲染规则与 Shader”清单，再按清单实施，不散落在临时讨论中。

## 1. 功能边界

HomePlayer 使用两层配置：

- `rules.json` 是声明式数据，决定何时使用某个渲染配置。
- `.glsl` / `.hook` 是 libplacebo 原生解析的 mpv 兼容 Shader，决定画面如何处理。

不引入 Lua、JavaScript、第三方 DLL 或任意 CPU 脚本。Basic、madVR、MPC VR 和独立原生输出不执行这些 Shader。共享 NV12/P010 硬解帧通过对应亮度/色度视图直接进入 libplacebo，不进行 CPU 回读或额外的逐帧拆分复制。

默认数据目录结构：

```text
%LOCALAPPDATA%\HomePlayer\render\
├─ rules.json
└─ shaders\
   └─ example.glsl
```

自定义数据目录迁移后，`render` 同样位于当前数据根目录。应用不会自动扫描视频旁脚本，也不会自动执行网络路径中的 Shader。

## 2. 快速方案与高级规则

播放页播放按钮右侧的箭头提供“自动（按规则）”“动画增强”“真人增强”“低码率修复”。选择内置方案即启用自定义渲染，不需要导入 Shader 或编辑 JSON；播放按钮本体仍只负责播放/暂停。

| 方案 | 固定处理链 |
| --- | --- |
| 动画增强 | CfL Prediction → Anime4K Clamp Highlights → Restore CNN M → Upscale CNN x2 M → adaptive-sharpen |
| 真人增强 | CfL Prediction → RAVU Lite AR r3 → SSimSuperRes → adaptive-sharpen |
| 低码率修复 | hdeband → NLMeans → FSRCNNX x2 8-0-4-1 → adaptive-sharpen |

“自动”只执行用户 `rules.json` 中第一条匹配的规则，不会猜测视频是动画还是真人。内置方案只读，选择会记住；管线信息可查看实际 Shader 和回退原因。ArtCNN、CuNNy、NNEDI3、SSimDownscaler、KrigBilateral、guided 等其余随包 Shader 可供高级规则引用。

内置文件位于程序目录 `render/shaders`，规则中使用 `builtin/shaders/...` 引用；该前缀始终读取随包文件，用户目录中的同名文件不会覆盖它。固定上游版本和许可证见 `third_party/shaders/README.md`。

高级自定义仍在“设置 → 播放”中：

1. 选择非 Basic 的基础渲染质量。
2. 启用“自定义渲染规则（高级）”。
3. 使用“导入 Shader”复制本地 `.glsl` / `.hook`，或手动放入用户 `render/shaders`。
4. 编辑用户 `render/rules.json`，然后点击“重新加载”。
5. 在播放页“更多 → 管线信息”检查请求配置、命中规则、实际 Shader 和回退原因。

示例：

```json
{
  "version": 1,
  "profiles": [
    {
      "id": "anime-upscale",
      "base": "highQuality",
      "shaders": [
        {
          "file": "shaders/contrast.glsl",
          "enabled": true,
          "parameters": {
            "strength": 1.1
          }
        }
      ]
    }
  ],
  "rules": [
    {
      "name": "SDR 放大到高分屏",
      "enabled": true,
      "profile": "anime-upscale",
      "all": [
        { "field": "source.transfer", "op": "eq", "value": "sdr" },
        { "field": "source.height", "op": "lte", "value": 1080 },
        { "field": "target.height", "op": "gte", "value": 1440 }
      ]
    }
  ]
}
```

对应 `shaders/contrast.glsl`：

```glsl
//!PARAM strength
//!DESC Contrast strength
//!TYPE DYNAMIC float
//!MINIMUM 0.0
//!MAXIMUM 2.0
1.0

//!HOOK MAIN
//!BIND HOOKED
//!DESC HomePlayer contrast

vec4 hook()
{
    vec4 color = HOOKED_texOff(0);
    color.rgb = (color.rgb - 0.5) * strength + 0.5;
    return color;
}
```

`base` 支持 `basic`、`performance`、`balanced`、`highQuality`，也兼容 `fast`、`default`、`high_quality` 写法。Basic 配置不能包含启用的 Shader。

## 3. 匹配顺序

优先级固定为：

1. 播放页“更多 → 渲染配置”或设置页选择的手动 Profile；
2. `rules` 中第一条匹配且启用的规则；
3. 无匹配时使用设置中的基础“渲染质量”，不加载 Hook。

第一条命中即停止，不合并多个 Profile。一个 Profile 内的 Shader 按数组顺序执行。手动 Profile 已从文件中删除时，回退到基础质量，不会改命中其他规则。

规则在打开文件、首帧元数据变化、目标尺寸/HDR 代际变化、设置变化和手动重载时求值。相同上下文不重复求值，不在逐帧热路径读取 JSON 或磁盘。

未知字段值不匹配。例如源传递函数为 `Unknown` 时，`source.transfer=sdr` 不会命中，不能把未知元数据当成 SDR。

## 4. 条件和操作符

规则支持：

- `all`：全部满足；空数组视为满足。
- `any`：至少一个满足；空数组不限制。
- `not`：单个条件取反。
- 操作符：`eq`、`ne`、`gt`、`gte`、`lt`、`lte`、`in`、`glob`。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `file.path` | 字符串 | 完整媒体路径 |
| `file.name` | 字符串 | 文件名 |
| `file.extension` | 字符串 | 扩展名 |
| `file.container` | 字符串 | 容器 |
| `file.duration` | 数值 | 时长（秒） |
| `source.codec` | 字符串 | 视频编码 |
| `source.width` / `source.height` | 数值 | 源宽高 |
| `source.fps` | 数值 | 帧率 |
| `source.pixelFormat` | 字符串 | `bgra32`、`nv12`、`p010` |
| `source.transfer` | 字符串 | `sdr`、`pq`、`hlg` |
| `source.interlaced` | 布尔 | 是否隔行 |
| `target.width` / `target.height` | 数值 | 实际渲染目标宽高 |
| `target.hdr` | 布尔 | 当前是否 HDR 输出 |
| `scale.width` / `scale.height` | 数值 | 目标/源缩放比例 |

`glob` 支持 `*`、`**`、`?`，路径比较不区分大小写；匹配设置 50 ms 超时。字符串数值按不依赖区域设置的格式解析，布尔值使用 JSON 布尔或 `true` / `false` 字符串。

## 5. Profile 和参数 UI

每个 Profile 包含：

- 唯一 `id`；
- 一个基础质量 `base`；
- 最多 16 个有序 Shader；
- 每个 Shader 的 `file`、可选 `enabled` 和数值 `parameters`。

参数支持 libplacebo 的有符号整数、无符号整数和浮点类型。未知参数、非整数写入整数参数、非有限值和越界值都会拒绝。

当前已加载 Shader 的 `PARAM` 会出现在设置页：

- `ENUM` 生成下拉框；
- 数值参数生成 NumberBox；
- 未写入 JSON 的参数使用 Shader 默认值；
- 修改后原子保存 `rules.json`，生成新内容版本并重新创建候选配置。

## 6. 原生生命周期和回退

实现使用随包的 libplacebo 7.360.1 / API 360：

- 完整绑定并校验 `pl_render_params`，x64 大小 288 字节，`hooks` 偏移 136，`num_hooks` 偏移 144。
- 使用 `pl_mpv_user_shader_parse` / `pl_mpv_user_shader_destroy` 管理 Hook。
- 使用 `pl_renderer_get_errors` 检查运行期 Hook 错误。
- 使用 `pl_renderer_flush_cache` 处理 Profile 和媒体切换。

每次更新先创建候选 Hook 集，只有首次成功渲染后才提交：

- JSON、文件或参数失败：保留上一份有效规则和当前已提交画面配置。
- 候选 Shader 首次执行失败：隔离该内容版本，继续使用上一份已提交配置。
- 已提交 Shader 后续失败：禁用自定义 Hook，回退到对应基础质量。
- libplacebo 本体失败：沿用既有 Basic 回退。
- 设备重建：销毁旧 GPU 资源并重新解析、编译 Hook。
- 同一失败版本不会逐帧重试；修改文件或参数生成新 SHA-256 内容版本后才重试。

## 7. 安全和资源限制

- `rules.json` 最大 1 MiB，单个 Shader 最大 1 MiB。
- 最多 64 个 Profile、256 条规则，每个 Profile 最多 16 个 Shader。
- 只接受 `render` 内的相对 `.glsl` / `.hook` 路径，拒绝绝对路径和目录穿越。
- 导入不会覆盖同名文件，自动追加数字后缀。
- JSON 显式 `null`、未知字段、未知操作符和非法参数均明确报错。
- GLSL 不是安全沙箱；死循环或恶意 Shader 仍可能重置 GPU。该功能默认关闭，只导入用户明确选择的文件。

## 8. 诊断和性能

管线信息同时显示：

- 功能开关和请求 Profile；
- 命中的自动规则或“手动优先”；
- 实际提交的 Profile、Shader 顺序和候选状态；
- 配置错误、隔离和回退原因；
- 最近一次 GPU 渲染耗时、滚动 60 次采样的 P95 和样本数。

GPU 时间戳每 30 帧低频采样、非阻塞读取。设备不支持、查询 Disjoint 或频率为 0 时显示 `Unknown`，不使用 CPU 时间代替。

## 9. 验证记录

- Core 规则、条件、存储、路径和异常输入测试全部通过。
- Playback 覆盖 API 360 ABI、普通 BGRA/NV12/P010、反色像素、动态参数、`WHEN=0`、多 Hook 顺序、参数越界和 GPU 编译失败回退。
- 在隔离数据目录启动真实 App，确认设置页开关、导入/重载入口和参数 NumberBox。
- 真实播放 320×240 红色 BGR 样本：命中 `invert-e2e` 后显示青色；参数从 1 改为 0 后 JSON 保存成功，最后一帧恢复红色。
- 当前 RTX 3090 的 D3D11 时间戳频率实测为 0，诊断按预期显示 `Unknown`。
- 17 个随包 Shader 均完成真实 D3D11 解析、编译和执行；动画、真人、低码率三条完整链均通过非黑像素断言。
- 使用真实 FFmpeg 硬解 NV12 和 LAV NV12 纯红帧分别验证无 Shader 与真人完整链的 RGB 输出；覆盖直接共享平面视图。
- 在隔离数据目录的真实 App 中选择播放按钮“动画增强”，确认设置持久化；冷启动纯红播放的颜色和几何正确，管线实际提交 `builtin.anime` 和全部五个 Shader。
- 修复 LAV 纹理 RCW 被提前释放导致的空引用，并将 libplacebo 异常堆栈写入渲染日志。
- 未知 YUV 颜色矩阵与 Basic 一样回退 BT.601，避免 libplacebo 将未标记帧当成 RGB；输出裁剪不再重复乘 CompositionScale，100%/125%/150%/200% 像素测试通过。
