# 媒体库改版方案

这份文档说明媒体库从「一次性全量卡片网格」改成「分页浏览 + 文件夹树 + 按视图随机播放 + 跨重启续播」要怎么改。先定语义和数据结构，实现按第 12 节顺序做。没写进「第一版不做」的，都要能真正点、真正生效。

## 进度

按第 12 节顺序逐项实现，每完成一个阶段单独提交，并在这里记下提交。

## 1. 现在什么样

媒体库页是 `src/HomePlayer.App/Pages/LibraryPage.xaml`，左栏 280px 只有库列表，右栏是搜索框 + 排序下拉 + 刷新 + 网格。

现在的数据路径：

1. `LibraryRepository.ListItems(libraryId)` 是 `SELECT * FROM MediaItem WHERE LibraryId = $id`，**没有 ORDER BY、没有 LIMIT**，一次读整库。
2. `LibraryPage.BindCards()` 在内存里过滤、排序，然后对**每一条**调用 `CreateCard()`。
3. `CreateCard()` 里立刻 `new BitmapImage` 并做 `FileInfo` 探测（`DecodePixelWidth = 480`）。图片缓存只有 200 条 LRU。
4. `GridView` 的容器是虚拟化的，但图片解码不是 —— 库一大，卡的是封面不是行数。
5. `MediaItemComparer.Compare(left, right, kind, byDate)` 只有两档排序，升降序写死。
6. `PlayCardAsync()` 把当前 `_cards` 全量塞进 `Playlist.Replace(paths, start)`。
7. `ApplyItemUpdates()` 逐条 `RemoveAt` + `FindInsertIndex` 插入；`FindInsertIndex` 注释写二分，实现是 `for` 线性扫描，最坏 O(n²)。
8. 播放进度在 `PlaybackController._resumeByPath`，是纯内存 `Dictionary`，**进程退出即丢**。
9. `LibraryRepository.Migrate()` 只有 `CREATE TABLE IF NOT EXISTS`，没有 `user_version`，加列只能手写 ALTER。
10. `HomePlayer.Playback` 只引用 `HomePlayer.Core` 和 `HomePlayer.Ffmpeg`，**不引用 `HomePlayer.Data`**。

第 10 条决定了进度持久化必须走接口注入，不能让 `PlaybackController` 直接拿 `LibraryRepository`。

## 2. 已确认的决策

| # | 问题 | 决策 |
|---|---|---|
| 1 | 分页形态 | 页码分页，支持输入指定页跳转 |
| 2 | 每页条数 | **固定**，默认 60，可选 30 / 60 / 100 / 200；不跟随窗口宽度 |

## 3. 「视图」的定义

整个页面只有一个视图概念，浏览、随机、播放队列都作用在它上面：

```
视图 = 库 + 文件夹（可空=库根）+ 递归开关 + 搜索词 + 排序
```

- 搜索**在当前文件夹和递归开关的范围内**生效，不是全库搜索。
- 随机播放取的是这个视图的完整结果集。
- 双击播放取的是这个视图的完整结果集，从被点项开始。
- 搜索、排序、切库、切文件夹、切递归开关 → 一律回第 1 页。

## 4. 数据库

### 4.1 迁移机制

`Migrate()` 改成 `PRAGMA user_version` 驱动的顺序链：

1. 先跑现有的 `CREATE TABLE IF NOT EXISTS`，保证老库的表结构都在。
2. 读 `PRAGMA user_version`，为 0 时视作 v1。
3. 按版本号顺序执行迁移，每个版本一个事务，执行完写回新的 `user_version`。

第一版只需要 v1 → v2。

### 4.2 v2 结构变更

```sql
ALTER TABLE MediaItem ADD COLUMN RelativeDir   TEXT    NOT NULL DEFAULT '';
ALTER TABLE MediaItem ADD COLUMN FileName      TEXT    NOT NULL DEFAULT '';
ALTER TABLE MediaItem ADD COLUMN AddedUtcTicks INTEGER NOT NULL DEFAULT 0;

CREATE INDEX IX_MediaItem_Library_Dir  ON MediaItem(LibraryId, RelativeDir);
CREATE INDEX IX_MediaItem_Library_File ON MediaItem(LibraryId, FileName);

CREATE TABLE Folder (
  LibraryId      TEXT    NOT NULL,
  RelativePath   TEXT    NOT NULL,   -- '' 表示库根
  ParentPath     TEXT,               -- NULL 表示库根
  Name           TEXT    NOT NULL,
  DirectCount    INTEGER NOT NULL,   -- 直接子项视频数
  RecursiveCount INTEGER NOT NULL,   -- 含所有子目录的视频数
  CoverPath      TEXT,
  CoverStamp     TEXT,               -- 生成封面时的输入指纹
  PRIMARY KEY (LibraryId, RelativePath)
);

CREATE INDEX IX_Folder_Parent ON Folder(LibraryId, ParentPath);

CREATE TABLE PlaybackState (
  Path            TEXT    PRIMARY KEY COLLATE NOCASE,  -- 绝对路径
  PositionSeconds REAL    NOT NULL,
  DurationSeconds REAL    NOT NULL,
  Finished        INTEGER NOT NULL,
  UpdatedUtcTicks INTEGER NOT NULL
);
```

`Path` 用 `COLLATE NOCASE` 是为了让 `D:\A.mkv` 和 `d:\a.mkv` 不重复。SQLite 的 `NOCASE` 只折叠 ASCII 大小写，中文路径不受影响，够用。

### 4.3 三个新列的用途

| 列 | 用途 | 为什么不能省 |
|---|---|---|
| `RelativeDir` | 目录过滤、树节点关联 | 现在只能靠 `LIKE 'dir/%'` 前缀猜，且无法排除更深层目录 |
| `FileName` | Raw 库按文件名排序、搜索 | 现在是计算属性（`Path.GetFileName`），SQL 里排不了、也索引不了 |
| `AddedUtcTicks` | 「最近添加」排序、未来「最近添加」区块 | 入库时间目前根本没记录 |

回填在 C# 里做：迁移时读行 → 用 `Path.GetDirectoryName` / `Path.GetFileName` 算 → 事务批量 update。不写 `rtrim` 那种 SQL 技巧。

老条目的 `AddedUtcTicks` 用 `MtimeUtcTicks` 近似（没有真实入库时间，用文件修改时间比全部并列成升级当天更合理）。

### 4.4 仓储接口

`LibraryRepository` 新增：

```csharp
int CountItems(string libraryId, string? relativeDir, bool recursive,
               string? search, LibraryFilter filter, bool finishedOnly? /* 见 §10 */);

IReadOnlyList<MediaItem> ListItemsPage(string libraryId, string? relativeDir, bool recursive,
                                       string? search, LibraryFilter filter,
                                       SortMode sort, int offset, int limit);

IReadOnlyList<string> ListAllPaths(string libraryId, string? relativeDir, bool recursive,
                                   string? search, LibraryFilter filter, SortMode sort);

IReadOnlyList<MediaFolder> ListChildFolders(string libraryId, string parentPath);
void ReplaceFolders(string libraryId, IReadOnlyList<MediaFolder> folders);

void UpsertPlaybackState(PlaybackState state);
IReadOnlyDictionary<string, PlaybackState> LoadPlaybackStates(int limit);
```

- `ListAllPaths` 只取 `RelativePath`（或绝对路径），供随机播放和队列使用，不读整行。
- `LoadPlaybackStates(limit)` 只预热最近 N 条（建议 2000），避免几万行全捞。
- `CountItems` 与 `ListItemsPage` 的 WHERE 条件必须共用同一个构造函数，避免两处不一致。

### 4.5 WHERE 构造注意点

- 目录过滤
  - 非递归：`RelativeDir = $dir`（根目录是 `''`）
  - 递归：`(RelativeDir = $dir OR RelativeDir LIKE $prefix ESCAPE '\')`，`$prefix = dir == "" ? "%" : dir + "/%"`
- 路径里的 `%` `_` `\` 必须转义，用 `ESCAPE '\'`。
- 搜索：`(Title LIKE $q ESCAPE '\' OR FileName LIKE $q ESCAPE '\')`。`Title` 对 Catalog 库是 TMDB 标题，Raw 库为空时回退 `FileName`。`%q%` 走不了索引，几万行可以接受。
- 排序统一走 `ORDER BY`，NULL 要显式后置，例如 `ORDER BY Year IS NULL, Year DESC`。

## 5. 分页

### 5.1 分页栏

```
«  ‹   1  …  4  5 [6] 7  8  …  100  ›  »      共 5,842 项   每页 60 ▾   跳至 [__] 页
```

- 左侧四个按钮：首页 `«`、上一页 `‹`、下一页 `›`、末页 `»`。
- 中间页码窗口：当前页 ±2，加首末页，空档处用 `…`。
- 右侧：总条目数、每页条数下拉（30 / 60 / 100 / 200）、常驻跳转输入框。

### 5.2 页码窗口算法（纯函数，放 `HomePlayer.Core/PagedView.cs`）

```
PageWindow(current, total):
  if total <= 9            → 1..total
  if current <= 5          → 1..7, …, total
  if current >= total - 4  → 1, …, total-6..total
  else                     → 1, …, current-2 .. current+2, …, total
```

- 相邻两个页码之间只剩 1 个空档时不插省略号，直接连上（避免 `1 … 3 4 5 … 100` 这种）。
- 省略号点击后变成输入框（与右侧常驻输入框同一个逻辑），回车或失焦生效。
- 输入非数字、空、越界一律裁剪到 `[1, TotalPages]`。

### 5.3 隐藏条件

- 总条目为 0，或只有 1 页时，整条分页栏隐藏。
- 切换任何视图参数后页码回 1，页码栏同步刷新。

### 5.4 数据加载

```
total = CountItems(view...)
page  = Clamp(requestedPage, 1, TotalPages(total, pageSize))
items = ListItemsPage(view..., offset: (page-1)*pageSize, limit: pageSize)
```

一页 60 条，封面可以整页解码，不再需要增量加载和图片懒加载。

## 6. 文件夹树

### 6.1 数据维护

`LibraryCoordinator.ReconcileCore()` 本来就会全量遍历目录（`VideoFiles.Enumerate`），在同一个方法里：

1. 从枚举出的文件路径推导出全部祖先目录（相对库根），含库根 `''`。
2. 每个目录算 `DirectCount`（直接子项视频数）和 `RecursiveCount`（含子目录）。
3. 与 `ListChildFolders` 的结果 diff：新增 → insert，计数变化 → update，消失 → delete 并删封面缓存目录。
4. 整个 diff 包在一个事务里。
5. 只写 `RecursiveCount > 0` 的目录（没有视频的目录不进树）。
6. `CoverStamp` 变化（子项集合或 mtime 变了）的目录进封面队列。

### 6.2 控件

- WinUI `TreeView`，**懒加载**：`Expanding` 事件里查一层 `ListChildFolders(libraryId, parentPath)`，用 `HasUnrealizedChildren` 控制是否有展开箭头。几千个目录也不卡。
- 节点文案：`Name`，右侧灰字显示 `RecursiveCount`；`DirectCount == RecursiveCount` 时只显示一个数字。
- 库根节点显示库名，展示全库数量。
- 右键节点：本文件夹随机播放 / 在资源管理器中打开。
- 展开状态随视图状态持久化（见 §11）。

### 6.3 递归开关

- 树顶部一个 `递归包含子文件夹` ToggleSwitch，全局生效。
- 关闭时：右侧列表只显示该目录的直接子项视频，树节点上的数字也切到 `DirectCount`。
- 打开时：切到 `RecursiveCount`。

### 6.4 其他规则

- 单视频文件夹**不**做扁平化，保持结构与磁盘一致。
- `Pending`（等探测/等缩略图）的条目照常显示，带「处理中」角标，不要藏起来。
- 切库时清空树并重建。
- 没有选中任何文件夹时，视图等价于「库根 + 当前递归开关」。

## 7. 文件夹封面

### 7.1 生成规则

| 库类型 | 封面来源 | 成本 |
|---|---|---|
| Raw | 直接子项按文件名排序取前 4 个，各取已有一帧（`FramePaths` 中间的 f4，没有则 f0），拼 2×2 | 纯 IO，不重新解码 |
| Catalog | 直接子项第一个的 `PosterPath` 单图 | 纯 IO |

- 直接子项不足 4 个时，向子目录递归借（否则剧集库里大量中间层目录封面空白）。
- 一个视频都没有、只有子目录时，用子目录里任意一个可用封面。
- 缓存路径：`%LocalAppData%\HomePlayer\cache\folder-thumbs\{hash(LibraryId + "|" + RelativePath)}\cover.jpg`，尺寸 480×270。

### 7.2 指纹与失效

- `CoverStamp` = 参与拼接的 itemId 列表 + 各自 `MtimeUtcTicks` 拼串的哈希。
- `Reconcile` 后比对，不一致就重建。
- 删库、删目录时按目录删 `folder-thumbs` 缓存；`CacheBytes()` / `ClearCacheAsync()` 覆盖该目录。

### 7.3 优先级

- 独立队列 + `SemaphoreSlim(1)`（与扫描的 `_maxParallel = 2` 分开）。
- 扫描进行中、播放进行中时让路（与 `SetPlaybackActive` 一致）。
- 封面生成失败不重试、不报错、不留空目录，下次 `Reconcile` 再试。

## 8. 随机播放与播放队列

### 8.1 随机播放

- 入口：右侧工具栏一个「随机播放」按钮（作用于当前视图），文件夹树节点右键一个。
- 语义：取当前视图的完整结果集（`ListAllPaths`），洗牌，随机起点，`Playlist.Replace`。
- 播完一轮按现有 `Repeat` 设置决定重洗还是停止，复用现有逻辑。
- 不排除已看。
- `Playlist.RebuildShuffle` 的 `OrderBy(random)` 换成 Fisher-Yates（现有实现有偏）。

### 8.2 播放队列

- 双击卡片：`ListAllPaths(当前视图)`，起点 = 被点那条在结果集里的序号。**不再用 `_cards`**。
- 右键「播放」同上。
- 右键「加入播放列表」不变，只加单条。
- 播放列表里的显示顺序就是视图排序结果（随机播放时是洗牌后的顺序）。

## 9. 播放进度持久化

### 9.1 分层

`HomePlayer.Playback` 不引用 `HomePlayer.Data`，所以在 `Core` 定义接口：

```csharp
public interface IPlaybackStateStore
{
    IReadOnlyDictionary<string, PlaybackState> LoadAll(int limit);
    void Save(PlaybackState state);          // 只写内存 pending，线程安全
    void Flush();                            // 落库
}
```

- `LibraryRepository` 实现它（或者包一层 adapter，保持 Repository 不依赖 Core 的 record 也行）。
- `PlaybackController` 构造函数加一个 `IPlaybackStateStore` 参数，`AppHost.Create` 里注入。
- 构造函数参数新增后，`HomePlayer.Playback.Tests` 里的构造调用要一起改。

### 9.2 写入时机

- `RememberPosition()` 原有调用点（`PlayPathsAsync` / `Stop` / `PlayCurrentAsync` 开头）写内存 pending。
- 后台 `PeriodicTimer` 每 10 秒 `Flush()` 一次。
- 暂停、切条、退出（`ShutdownAsync` / `AppHost.DisposeAsync`）时立即 `Flush()`。
- 不在每帧或每秒写 SQLite。

### 9.3 判定规则

- 复用 `PlaybackResume.Position(position, duration)`：`< 5s` 或距结尾 `≤ 5s` 返回 `null`。
- 返回 `null` 且是因为「距结尾 ≤ 5s」→ 标记 `Finished = 1`，进度写 0。
- 文件 `Size` 或 `MtimeUtcTicks` 变化（走 `Reconcile` 的 `MarkChanged`）→ 该条进度作废。
- 移动/重命名文件 → 路径键变了，旧进度自然失效，不做迁移。

### 9.4 UI

- 卡片封面底部一条 3px 进度线，按 `PositionSeconds / DurationSeconds` 填充。
- `Finished` 的卡片在右上角加「已看」角标。
- 冷启动后打开库内视频自动续播，不额外做「继续观看」入口（卡片进度线就是提示）。
- 库外文件（拖放、命令行、文件关联打开）同样记录，但不出现在库里。

## 10. 筛选与视图状态

### 10.1 筛选

工具栏加一个筛选下拉，按库类型给选项：

- 通用：全部
- 所有库：失败（`Status = Failed`）
- Catalog 库：待核对（`MatchStatus = NeedsReview`）
- 有进度记录的库：未看（`Finished = 0` 且 `PositionSeconds < 5`）

筛选与搜索、排序、分页同时生效，同样回第 1 页。

### 10.2 视图状态

`AppSettings` 增加 `LibraryViewState`：

```csharp
public sealed class LibraryViewState
{
    public string? LibraryId { get; set; }
    public string? FolderPath { get; set; }
    public bool Recursive { get; set; }
    public int Page { get; set; } = 1;
    public int PageSize { get; set; } = 60;
    public string SortMode { get; set; }
    public List<string> ExpandedFolders { get; set; } = [];
}
```

- 选中库、文件夹、页码、排序、每页条数、树展开节点，启动时恢复。
- **搜索词不恢复**。
- 保存时机：`SaveSettings()`（退出时）+ 页面切走时。

## 11. 增量刷新

分页之后放弃精细插入，避免 C# 比较器与 SQL `ORDER BY` 两套语义打架：

- 删除 `ApplyItemUpdates` / `FindInsertIndex` / `IndexOfCard` 那套逻辑。
- `LibraryCoordinator.Changed` 触发时，不再改动当前卡片集合，只记一个 `_pendingUpdate` 计数。
- 页面顶部显示「有 N 项更新，点击刷新」；用户点击或主动切页/搜索/排序时 `LoadPage()` 重查。
- 当前页条目被删空时自动回退一页并重查。
- 总数变化（`CountItems` 重算）可以低频做，比如提示条出现时顺带刷新。

## 12. 实现顺序

每一步都要能编译运行，界面上不出现点了没反应的启用按钮。每步做完构建、安装、启动，由使用者上机确认后再进入下一步。

### 阶段 0：数据库迁移机制 + `MediaItem` 补列

- [x] `Migrate()` 改成 `PRAGMA user_version` 顺序链，v0 视为 v1
- [x] v1 → v2：`ALTER TABLE` 加 `RelativeDir` / `FileName` / `AddedUtcTicks`
- [x] C# 回填三个新列（`AddedUtcTicks` 用 `MtimeUtcTicks`），事务包裹
- [x] 建两个 `MediaItem` 索引
- [x] `AppModel.cs` 里 `MediaItem` 加三个属性
- [x] 扫描新增条目时写入三个字段（`LibraryCoordinator.InsertItem` 路径）
- [x] 测试：从 v1 老库升级后数据完整、重复启动不重复迁移

**验收**：老库启动正常，媒体库页面行为与现在一致，无数据丢失。

### 阶段 1：分页 + 排序/搜索下推 + 分页栏

- [ ] `SortMode` / `LibraryFilter` 枚举，`MediaItemComparer` 改为 `SortMode` 驱动

- [ ] `LibraryPage` 改 `LoadPage()`，替换 `BindCards()`

## 15. 怎么验收

手动，用本地一个真实库即可：

1. 库有几百条、几十页时，翻页流畅，第 1/中间/最后页的页码压缩都对，输入 `999` 跳到最后页。
2. 每页切到 30 / 100 / 200，总页数正确，当前页不越界。
3. 搜索后只在当前文件夹范围内出结果，且回到第 1 页；清空搜索恢复。
4. 文件夹树与资源管理器里的目录结构一致；折叠再展开不卡；增删一个子目录后几秒内反映。
5. 递归开关切换后，列表条数、树节点数字同步变化。
6. Raw 库各文件夹有 2×2 封面；删掉该目录一个视频后封面重建。
7. 在文件夹视图点随机播放，只在该文件夹（或递归范围）内随机；整库随机时不出现视图外的文件；搜索结果里随机只抽搜索结果。
8. 从第 3 页双击一个视频，播放列表包含全部页的结果，下一首按视图排序走。
9. 播到中途关闭程序，重启后从原位置继续；播完的条目进度清零并显示已看。
10. 手动删掉一个视频文件，当前页出现「有 1 项更新」，点击后刷新；删空后自动退一页。
11. 关闭程序再打开，回到上次的库、文件夹、页码、排序、每页条数。
12. 筛选「失败」能列出扫描失败的条目，「未看」不含已看完的。
