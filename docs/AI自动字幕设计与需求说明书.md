# HomePlayer AI 自动字幕设计与需求说明书

> 状态：评审稿
> 适用范围：HomePlayer Windows 桌面版
> 关联文档：《AI 功能执行计划》《播放引擎架构设计》《播放器控件栏》
> 说明：本文描述目标设计，不表示相关能力已经实现，也不构成版本发布承诺。

## 1. 文档目的

本文定义一套可实际使用的 AI 自动字幕与翻译功能。系统必须先检查已有字幕，再按最短必要路径处理：

```text
路径 A：已有可解析文本字幕
选择外挂或内嵌文本字幕
→ 保留原时间轴，直接执行本地或经授权的云端翻译
→ 编辑、校对与双语对照
→ 播放预览、保存和导出
（不需要语音识别，不读取整部音频）

路径 B：没有可用文本字幕，或用户明确要求重新识别
选择媒体与音轨
→ 选择识别模型和源语言
→ 提取音频、检测语音、执行识别
→ 生成带时间戳的原始转写
→ 标点、分段和字幕排版
→ 可选翻译、编辑与校对
→ 播放预览、保存和导出
```

本文同时给出产品需求、交互流程、模块边界、数据结构、任务语义、缓存规则、隐私边界、质量指标和验收方案，供范围评审、技术选型和分阶段实施使用。

“自动字幕”包括**文本字幕直接翻译**和**自动语音识别（ASR）生成字幕**两条路径。已有文本字幕时默认直接翻译；PGS/VobSub 等位图字幕不能直接作为文本翻译输入，其 OCR 不属于 ASR，不混入本功能首版，但用户仍可选择从音频执行 ASR。

## 2. 背景与现有约束

### 2.1 与现有 AI 规划的关系

《AI 功能执行计划》当前将 M4 定义为“英语文本字幕到中文字幕”，无字幕语音识别列在后续扩展中。本说明书将 M4 扩展为多语言字幕处理，并拆成可以独立交付、随后汇合的两条链：

```text
M1 最小 AI 基础设施
├─ M4A 已有文本字幕的多语言直接翻译、校对与导出
└─ M4B 无字幕语音的多语言识别、校对与导出
          ↓
     统一进入翻译、双语和编辑链
          ↓
       M5/M6 AI 配音
```

推荐先交付 M4A，以较低成本验证本地翻译、术语、编辑和播放闭环；M4B 不再阻塞已有字幕的翻译。AI 识别文本还可供台词搜索、内容摘要、场景定位和无字幕配音复用，但这些下游能力不应阻塞第一条字幕闭环。

### 2.2 可复用能力

- 使用 FFmpeg 对本地文件和受支持输入进行解封装、音频解码与重采样。
- 使用现有 `MediaTrack.StableId` 标识音轨，不能只保存容易变化的流序号。
- 使用现有 `SubtitleCue`、`SubtitleTrack`、`SubtitleSession` 和文本字幕解析能力完成显示与导出衔接。
- 使用现有每文件字幕偏好保存生成字幕的选择、开关和延迟。
- 使用现有数据库迁移、备份、诊断、私有依赖校验和测试体系。
- 复用 M1 的模型清单、任务调度、缓存、磁盘配额和能力状态，不另建一套语义冲突的任务中心。

### 2.3 必须保持的边界

- 自动字幕与翻译是独立的离线/后台处理链；ASR 不依赖正在播放的 PCM，两者都不侵入解码、时钟和渲染热路径。
- AI 功能关闭、识别失败或翻译失败时，现有字幕选择、播放、seek、截图和音轨行为完全不变。
- 不自动覆盖原视频、内嵌字幕、用户已有外挂字幕或人工修改。
- 不默认上传完整媒体，不默认处理整个媒体库，不默认下载全部模型。
- madVR 等不支持 WinUI 字幕叠层的输出不得伪装支持生成字幕的播放预览；文件生成和导出仍可独立可用。

## 3. 产品目标与成功标准

### 3.1 产品目标

1. 用户无需理解 ASR、VAD、采样率或模型运行时，即可为常见本地媒体生成可用字幕。
2. 默认可离线运行，处理范围、模型、语言和输出结果清晰可控。
3. 自动识别结果不是一次性黑盒：用户能定位、试听、修改、撤销、局部重做和导出。
4. 长任务可暂停、继续、取消和断点恢复，失败不会破坏已有结果。
5. 生成字幕可追溯至源文件、音轨、模型、参数和原始识别分段。
6. 识别和翻译结果可复用，模型或参数变化时只失效必要范围。
7. 后台 AI 工作不得破坏稳定播放路径，资源不足时明确让路或等待。

### 3.2 用户可感知成功标准

- 用户从播放页发起任务，完成后能直接启用生成字幕，无需手工寻找产物文件。
- 用户能从任意一句字幕跳转到对应画面并反复试听该句。
- 应用重启后，未完成任务和已编辑内容仍然存在，不重复写入已完成分段。
- 同一文件重新打开时，可以选择此前生成的字幕版本。
- 云端处理前，用户能知道将发送什么、发送多少、发送到哪里。
- 对不支持或无法保证的能力，界面明确说明原因，不显示虚假成功或虚假精度。

## 4. 范围与优先级

### 4.1 完整目标能力

| 能力 | 内容 |
|---|---|
| 媒体输入 | 本地及现有 SMB/UNC 视频、音频文件；选择内嵌音轨；自定义时间范围 |
| 语音识别 | 本地模型、自动/指定语言、语音检测、标点和数字规范化、分段或词级时间戳 |
| 字幕整理 | 语义断句、行长与阅读速度约束、重复和疑似幻觉标记、低置信度定位 |
| 编辑校对 | 文本编辑、拆分、合并、插入、删除、时间调整、试听、撤销/重做、搜索替换 |
| 播放集成 | 生成结果作为独立字幕来源启用，记住每文件选择，保留原字幕可回退 |
| 翻译 | 单语翻译、双语对照、术语表、局部重译，复用现有 M4 翻译约束 |
| 导出 | SRT、WebVTT、TXT、带溯源信息的 JSON；ASS 作为后续格式 |
| 任务管理 | 队列、并发限制、暂停、继续、取消、重试、断点续作、失败分段重做 |
| 批量处理 | 多选文件、当前季或播放列表；逐项隔离失败，不默认全库处理 |
| 模型管理 | 按需下载、哈希校验、更新、删除、硬件适配和许可证展示 |
| 云端扩展 | 用户显式授权的云端 ASR/翻译 Provider，与本地 Provider 共用文档和编辑模型 |
| 可选增强 | 说话人区分、自定义词汇、局部重识别、边生成边预览 |

### 4.2 P0：首个可发布闭环

P0 必须同时覆盖“已有字幕直接翻译”和“无字幕语音识别”两个入口：

- 选择外挂或内嵌文本字幕，保留原 cue 时间轴，直接使用本地模型翻译；支持仅译文和原文 + 译文。
- 单个本地媒体文件、单条内嵌音轨、全片或自定义范围识别。
- 官方审核的本地多语言 ASR 与翻译模型；自动语言检测和手工指定语言。
- P0 语言矩阵不得只含中英文，首发评估至少覆盖中文普通话、英语、日语、韩语、葡萄牙语、西班牙语、法语、德语、俄语和意大利语；每种语言分别通过质量门禁后才标记为正式支持。
- 流式音频提取、VAD/分段、识别、基础标点、字幕 cue 生成。
- 任务进度、暂停/继续/取消/重试、应用重启恢复、磁盘与错误提示。
- 字幕编辑器、单句试听、文本和时间编辑、撤销/重做、自动保存。
- 生成或翻译结果在 HomePlayer 支持的播放输出中启用。
- SRT、WebVTT、TXT 导出和内部 JSON 工程数据。
- 识别和翻译均可完全本地处理，模型下载校验、日志脱敏和分语言质量报告。

### 4.3 P1：效率与质量增强

- 影片级/剧集级术语表、翻译风格和多轮上下文优化。
- 批量生成或翻译、按季处理和失败项单独重试。
- 自定义识别词汇/热词、人名和专有名词提示。
- 局部范围重识别、局部重译并保留编辑历史。
- 云端 ASR/翻译 Provider，按任务授权，仅作为可选扩展。
- 说话人区分和说话人标签编辑。
- 低置信度、长句、过快字幕等质量检查面板。
- ASS 导出和更丰富的字幕排版选项。

### 4.4 P2：后续扩展

- 边生成边从当前位置预览，以及有明确缓冲状态的准实时生成。
- 多语言频繁混合内容的自动逐段语言识别。
- 字幕驱动的台词搜索、摘要和章节定位。
- 面向听障场景的非语音声音描述；必须由模型实际输出支持，不能把普通 ASR 结果包装成完整 SDH。

### 4.5 明确不在本功能中

- 位图字幕 OCR；应另立“字幕 OCR”工作包。
- DRM 破解、绕过访问控制或处理用户无权访问的内容。
- 默认上传完整视频或默认启用云端服务。
- 自动改写原视频、将字幕压入画面或重封装内嵌字幕；如需提供，属于独立导出功能。
- 根据声音自动断言真实人物身份；说话人分离只能给出“说话人 1”等匿名标签。
- 在无真实指标时承诺“逐字准确”“零延迟”或“所有语言通用”。

## 5. 用户与核心场景

### 5.1 普通观影用户

> 电影没有可用字幕，我希望点击一次，自动识别日语、韩语、葡萄牙语或其他影片语言，完成后直接观看或继续翻译成中文。

系统隐藏底层分段和采样细节，只展示推荐模型、预计下载量、磁盘需求、处理范围和可理解的进度。

### 5.2 外语学习与双语用户

> 影片已经有日语外挂字幕，我要直接生成中文字幕并保留双语，不需要重新听写；发现人名错误后可以统一修正。

已有文本字幕直接进入翻译，原文和译文保持映射。修改原文后可选择仅重译受影响 cue，不覆盖未受影响的人工译文；没有文本字幕时才先生成原文字幕。

### 5.3 字幕校对用户

> 我需要按时间顺序检查低置信度句子，试听、修改、调整切分，再导出 SRT。

编辑器必须支持键盘操作、撤销、搜索、逐句试听和失败恢复，不能只提供一个大文本框。

### 5.4 剧集整理用户

> 我选择当前季批量生成字幕，其中一集失败不影响其他集，之后可以只重试失败集。

批量任务使用相同或允许逐项覆盖的配置，默认有界并发，不自动扩大至整个媒体库。

### 5.5 隐私敏感用户

> 我只允许本地识别和翻译，不上传音频、标题、字幕或媒体路径。

本地模式下除用户主动下载/更新模型外，识别和翻译过程都不需要网络；云端密钥和文本不得进入普通诊断日志。

## 6. 总体用户流程

### 6.1 首次使用与路径选择

```text
播放页“字幕”→“AI 自动字幕 / 翻译”
→ 检查已有外挂与内嵌字幕

已有可解析文本字幕：
→ 默认选择“翻译已有字幕”
→ 选择源字幕轨、源语言（可自动检测）和目标语言
→ 选择本地翻译模型，保留原时间轴并创建翻译任务

没有文本字幕，或用户主动切换到“从音频重新识别”：
→ 选择音轨、识别语言、处理范围和可选目标语言
→ 选择本地识别模型，创建识别任务

只有 PGS/VobSub 位图字幕：
→ 说明首版不能直接翻译位图文字
→ 提供“从音频生成字幕”，不静默把位图交给文本翻译器

两条路径汇合：
→ 下载并校验所需模型（如尚未安装）
→ 后台处理，可离开页面
→ 校对、双语预览、启用字幕或导出
```

已有文本字幕时不得强制用户选择音轨、下载 ASR 模型或执行语音识别。首次设置页只要求做必要决策，高级参数放入折叠区，不提供无法解释的大量模型参数。

### 6.2 再次使用

- 对同一源文件和音轨展示已有字幕文档、语言、模型版本、更新时间和完成范围。
- 提供“使用”“继续校对”“导出”“重新生成”“删除文档”。
- 参数相同且缓存有效时，不重复识别；重新生成必须说明是复用、局部失效还是全量重做。
- 自动打开最近文档不覆盖用户当前手动选择的字幕轨；只有用户选择“完成后启用”且当前选择未再变化时才自动切换。

### 6.3 处理中离开或退出

- 离开播放页不取消任务，可在任务中心查看。
- 退出应用时进入有界停止和检查点保存；未完成分段标记为可恢复，不标记为成功。
- 重启后按用户策略恢复：默认等待用户继续，避免启动即占用 GPU；可选择自动恢复本地任务。
- 已完成且通过校验的分段直接复用，临时文件不完整时只重做对应分段。

## 7. 功能需求

以下“必须”为验收约束，“可以”为允许实现的可选体验。

### 7.1 输入与任务配置

**ASR-IN-001：媒体选择。** 必须支持从播放页、媒体库项目右键和任务中心新建任务；P0 每次处理一个文件。

**ASR-IN-002：音轨选择。** 必须列出可解码音轨的标题、语言、声道和稳定标识。默认选择当前播放音轨；无当前会话时使用自动音轨并显示选择结果。

**ASR-IN-003：无音频处理。** 无音轨、音轨不可解码或所选流不是音频时不得创建识别任务，必须给出具体原因和可选操作。

**ASR-IN-004：处理范围。** 必须支持全片、从当前位置到结尾、自定义开始/结束时间。范围必须限制在媒体有效时间线内，并明确跨文件章节等暂不支持的时间线。

**ASR-IN-005：识别语言。** 必须支持“自动检测”和手工指定。自动检测应使用有代表性的语音片段，不应只依赖片头；结果必须展示检测语言和可信度，低可信度时允许用户修改后继续。不得选用 `.en` 等英语专用模型承担多语言任务。

**ASR-IN-006：多语言矩阵。** P0 至少评估并争取正式支持中文普通话、英语、日语、韩语、葡萄牙语、西班牙语、法语、德语、俄语和意大利语。模型论文或列表中“声称支持”不等于 HomePlayer 正式支持，必须按语言实测；未通过的语言可标为实验或不开放。粤语、方言和频繁混合语言单独列能力，不与普通话混为一项。

**ASR-IN-007：输出模式。** P0 支持原文单语、仅译文和“原文 + 译文”。识别语言、已有字幕源语言和翻译目标语言分开配置；目标默认简体中文，但允许选择其他已验证语言，不限制为“只能翻译成中文”。

**ASR-IN-008：高级参数。** 至少提供模型/档位、设备自动选择、VAD 开关（仅在模型链允许时）、词级时间戳开关、每行长度和最大行数。默认值适用于普通用户。

**ASR-IN-009：预检。** 开始前必须检查模型状态、磁盘预算、源文件可读性、所选字幕或音轨有效性、Provider 语言/方向能力及云端授权。预检失败不能留下 Running 任务。

**ASR-IN-010：已有文本字幕优先。** 检测到可解析的外挂或内嵌文本字幕时，默认入口必须是“翻译已有字幕”，直接保留时间轴并翻译，不执行 ASR。用户仍可明确选择“从音频重新识别”，例如原字幕质量差或需要重新生成时间轴时。

**ASR-IN-011：位图字幕。** PGS/VobSub 不能交给文本翻译器假装处理；首版提示 OCR 未纳入，并提供 ASR 替代路径。

### 7.2 音频提取与标准化

**ASR-AUD-001：独立读取。** 必须通过独立、有界、可取消的 FFmpeg 读取链提取所选音轨，不能从正在播放的音频缓冲偷偷复制数据。

**ASR-AUD-002：模型输入。** 按 Provider 契约重采样为模型要求的格式；常见本地 ASR 使用 16 kHz、单声道 PCM。界面不暴露这些实现细节。

**ASR-AUD-003：有界存储。** 默认流式分块处理，不为长片无条件创建完整无损 WAV，不把整部影片 PCM 一次性载入内存。

**ASR-AUD-004：时间基准。** 每个音频块必须携带源时间线中的 64 位开始时间、时长和 TimeBase；重采样后的样本位置必须能映射回媒体时间。

**ASR-AUD-005：多声道。** 首版使用明确的下混策略；不得只取第一个声道而丢弃对白主声道。Provider 若支持多声道，必须声明实际处理方式。

**ASR-AUD-006：异常与取消。** 打开、读取、seek、解码和重采样都必须有取消与超时；SMB 中断、文件离线和损坏包不得造成永久卡死。

**ASR-AUD-007：播放资源。** 默认同文件正在播放时暂停后台音频提取；用户允许后台处理后仍须遵守播放性能 Profile。

### 7.3 语音检测与识别

**ASR-REC-001：VAD。** 使用语音活动检测或模型等效机制跳过明显无语音区间，减少音乐、噪声和静默造成的虚构文本。

**ASR-REC-002：分段。** 分段长度和重叠由模型能力决定。相邻分段重复内容必须通过对齐和来源映射消除，不能简单字符串替换。

**ASR-REC-003：原始结果。** 保存未排版的分段文本、开始/结束时间、可用的词级时间戳、语言、置信度和模型信息。原始结果与字幕 cue 分开保存。

**ASR-REC-004：时间戳真实性。** 模型只提供段级时间戳时，不得把插值结果标记为真实词级时间戳；词时间必须标明 `Native` 或 `Estimated`。

**ASR-REC-005：文本规范化。** 标点恢复、数字/单位规范化和大小写处理应按语言及 Provider 能力启用；原始转写应可追溯，后处理不可悄悄改变原意。

**ASR-REC-006：疑似幻觉。** 对高重复、无语音区长文本、异常置信度和分段边界重复进行标记或按明确规则过滤。被过滤内容须可诊断，不得导致整片静默缺字。

**ASR-REC-007：部分结果。** 每个成功分段立即形成检查点；后续分段失败时保留前面结果，任务可标记为 Completed 并带警告，或按失败策略等待重试，但必须清楚显示覆盖范围。

**ASR-REC-008：局部重做。** P1 支持对选中时间范围重新识别。新结果进入新修订版本，用户确认替换前不得覆盖人工编辑。

### 7.4 字幕 cue 生成与排版

**ASR-CUE-001：从转写到字幕。** cue 生成是独立、可重复执行的纯处理阶段。修改排版参数不应重新运行 ASR。

**ASR-CUE-002：断句。** 优先在标点、自然停顿和说话人边界断句，再依据词级时间戳处理超长句；不得仅按固定字符数硬切。

**ASR-CUE-003：时间约束。** cue 必须满足 `0 ≤ Start < End ≤ 媒体有效范围`，按时间排序。默认不重叠；确需重叠时必须显式支持并标记。

**ASR-CUE-004：建议默认排版。** 初始建议为最多 2 行、单 cue 0.8–7 秒、目标 1–6 秒、相邻 cue 间隔约 80 ms；具体阈值按语言 Profile 配置，不写死在 UI 中。

**ASR-CUE-005：行长与阅读速度。** 中文等 CJK 与拉丁文字使用不同行长和每秒字符数预算。超出预算时优先重新拆分，不能无提示地高速闪显。

**ASR-CUE-006：边界保护。** 不应为了获得最小间隔而大幅压缩真实对白时间；无法满足约束时保留较合理时间轴并生成质量警告。

**ASR-CUE-007：文本清理。** 移除多余空白和控制字符，统一换行；不得把 ASS 样式注入普通 AI 文本 cue。

**ASR-CUE-008：映射。** 每条 cue 必须能追溯到一个或多个原始识别分段；拆分、合并和重排后仍保留映射。

### 7.5 字幕编辑器

**ASR-EDT-001：三栏工作区。** 推荐布局为：顶部任务/质量信息，中部视频与当前字幕预览，下部虚拟化 cue 表格；右侧可折叠属性和问题面板。

**ASR-EDT-002：表格字段。** 至少显示序号、开始、结束、时长、正文、置信度和警告；P1 可显示说话人和译文。

**ASR-EDT-003：定位与试听。** 单击 cue 定位视频；提供“播放当前句”“循环当前句”“上一句/下一句”。试听可设置前后留白，不改变主任务数据。

**ASR-EDT-004：文本编辑。** 支持原地编辑和多行文本；保存后即时刷新预览。空文本默认视为待删除或无效，不生成空白 cue。

**ASR-EDT-005：结构操作。** 支持拆分、与上一句/下一句合并、插入、删除。拆分优先使用词级时间戳；无词级时间戳时标记为估算并允许人工调整。

**ASR-EDT-006：时间操作。** 支持编辑开始/结束、当前句整体平移、选中范围平移和整体延迟。必须防止负时间、倒置和意外重叠。

**ASR-EDT-007：撤销/重做。** 所有编辑和批量操作必须进入统一撤销栈，至少覆盖当前会话；已保存修订在重启后仍可恢复。

**ASR-EDT-008：搜索替换。** 支持全文查找、逐个替换和全部替换；“全部替换”必须可一次撤销。P1 支持只替换原文或译文。

**ASR-EDT-009：质量导航。** 可筛选低置信度、超长、过短、阅读过快、重叠、重复和识别失败范围，并提供“下一个问题”。

**ASR-EDT-010：自动保存。** 编辑先写内存，再以短延迟批量落库；切换文档、退出和崩溃恢复边界必须立即刷新。保存失败必须保留未保存内容并提示。

**ASR-EDT-011：大文档性能。** 列表必须虚拟化，1 万 cue 文档的滚动、搜索和单条编辑不得触发整表重建或全量文件重写。

**ASR-EDT-012：修订。** 每次 AI 重识别、重排版、重译或批量替换形成修订记录；普通逐键输入可合并为一个编辑事务，避免修订爆炸。

### 7.6 播放集成

**ASR-PLY-001：独立来源。** 生成字幕以独立文档/外挂字幕产物接入 `SubtitleSession`，不得伪装成原视频内嵌轨。

**ASR-PLY-002：菜单展示。** 字幕菜单显示“AI 生成”、语言、完成范围及是否存在更新；不覆盖原外挂和内嵌字幕项。

**ASR-PLY-003：启用与回退。** 用户可随时切回原字幕或关闭字幕。AI 文件损坏时记录错误并回退到此前有效选择，不导致播放失败。

**ASR-PLY-004：偏好保存。** 复用每文件字幕路径、开关和延迟偏好；文件变化导致文档失效时不得继续自动选择旧字幕。

**ASR-PLY-005：seek。** 使用现有字幕会话与 Epoch 清理语义，seek 后不得显示旧时间线 cue。

**ASR-PLY-006：外部输出。** 对不支持 WinUI 字幕叠层的路线显示限制；可以引导导出后由外部工作流使用，但不假装已经内嵌或压入。

**ASR-PLY-007：截图。** 生成字幕显示后遵循现有“截图是否包含字幕”设置，不改变源帧截图语义。

### 7.7 已有字幕直接翻译与双语

**ASR-TRN-001：直接输入。** 必须接受现有外挂和内嵌文本字幕作为独立任务输入，不需要音频、ASR 模型或识别过程。源字幕可以来自用户当前选择，也可以由用户在任务向导中另行选择。

**ASR-TRN-002：时间轴保留。** 直接翻译默认不改变原 cue 的开始、结束和顺序，不合并后错误回写时间；只有用户主动执行“重新断句/排版”时才创建新的排版修订。原文、译文和原 cue 必须逐条可追溯。

**ASR-TRN-003：文本与样式。** 清理样式标记和重复文本只用于模型输入，不修改原字幕文件。P0 导出 SRT/VTT 时不承诺保留 ASS 特效；ASS 样式保留或重建属于 P1 的明确能力。

**ASR-TRN-004：本地翻译。** P0 必须提供完全本地的翻译 Provider。模型下载完成后，断网时仍能翻译已有字幕和识别文本；云端 Provider 不是翻译功能的前置条件。

**ASR-TRN-005：翻译上下文。** 使用有界上下文、场景或邻近 cue 处理指代和语气，支持忠实/自然口语风格及术语表。批量提交必须保留结构化 cue 映射，不允许模型自由返回无法对应的整段文章。

**ASR-TRN-006：映射稳定。** 翻译针对稳定 CueId 或原始分段映射，不能仅按数组下标关联，避免拆分/合并后错位。模型返回缺失、重复或越界 ID 时不得静默错位保存。

**ASR-TRN-007：人工修改。** 原文变化只使相关译文失效；人工译文不得被后台任务自动覆盖。局部重译只提交用户确认的范围。

**ASR-TRN-008：多语言方向。** 至少对首发语言矩阵中的语言提供“源语言 → 简体中文”的实测，并按模型能力开放其他目标语言。源语言自动检测不确定时允许手工纠正，不强制先转英语再翻译。

**ASR-TRN-009：失败降级。** 翻译失败保留完整原文字幕和已完成译文，不将已有字幕或识别任务整体标记为无产物。

**ASR-TRN-010：双语导出。** 明确行顺序和格式，默认原文在上、译文在下；导出前提供预览。

### 7.8 导出与产物管理

**ASR-EXP-001：格式。** P0 支持 SRT、WebVTT、纯文本 TXT 和内部 JSON；P1 支持基础 ASS。导出编码默认 UTF-8。

**ASR-EXP-002：内容选择。** 可选择原文、译文或双语、完整或当前完成范围、是否包含说话人标签。

**ASR-EXP-003：不覆盖。** 默认导出到用户选择的位置；同名时要求确认，不静默覆盖。不得默认写回可能只读的媒体目录。

**ASR-EXP-004：原子写入。** 先写临时文件再替换目标；失败不留下被当作正式成品的半文件。

**ASR-EXP-005：JSON 溯源。** JSON 至少包含文档/修订、源指纹、音轨身份、模型和参数、cue 时间、文本、分段映射、置信度、词时间来源和警告。

**ASR-EXP-006：删除。** 删除 AI 文档只删除应用内文档和其私有产物，不删除媒体或用户另行导出的文件；操作前说明影响。

### 7.9 批量任务

**ASR-BAT-001：范围。** P1 支持媒体库多选、当前季和当前播放列表，不提供默认“一键全库”。

**ASR-BAT-002：逐项隔离。** 单文件失败不取消整个批次；批次报告显示成功、带警告、失败、取消和跳过数量。

**ASR-BAT-003：已有结果。** 默认跳过完全匹配的有效结果，允许用户明确选择重新生成；不得仅因文件存在就跳过不同语言或不同音轨任务。

**ASR-BAT-004：资源。** 全局并发有界，默认同时识别 1 个文件；模型下载和媒体扫描不能绕过统一资源预算。

## 8. 设置与默认策略

建议新增“设置 → AI → 自动字幕”，包括：

| 设置 | 建议默认值 |
|---|---|
| AI 自动字幕开关 | 关闭，遵循 AI 总开关 |
| 默认 Provider | 本地 |
| 默认识别语言 | 自动检测 |
| 默认模型 | 按硬件推荐，未下载时不自动创建任务 |
| 计算设备 | 自动；允许限定 CPU/GPU |
| 播放时后台任务 | 暂停 |
| 同时识别任务数 | 1 |
| 完成后启用字幕 | 询问/本次可选，不全局强制 |
| 重启后恢复任务 | 等待用户继续 |
| 临时缓存配额 | 使用 M1 全局 AI 配额 |
| 保留音频缓存 | 默认不保留 |
| 云端处理 | 关闭，每个任务单独授权 |
| 自动下载模型更新 | 关闭；只检查并提示 |
| 默认导出格式 | SRT，UTF-8 |

模型下载必须展示用途、版本、文件大小、来源、许可证、运行依赖和硬件需求。只允许官方审核清单，不执行模型包中的任意脚本，不开放任意第三方代码安装。

## 9. 技术架构

### 9.1 模块划分

建议新增 `HomePlayer.AI` 项目，避免把模型和任务逻辑堆入 `HomePlayer.App`：

```text
HomePlayer.App
├─ 自动字幕向导、编辑器、模型页、任务中心
└─ 调用 AISubtitleController / 查询只读快照
                    │
HomePlayer.AI
├─ AISubtitleController        用例编排、参数校验、状态迁移
├─ AiTaskScheduler             队列、并发、暂停、恢复、资源让路
├─ ModelManager                清单、下载、校验、设备能力
├─ AudioExtractionService      适配 FFmpeg 音频读取
├─ SpeechRecognitionProvider   本地/云端 ASR 抽象
├─ Vad / PostProcessor         VAD、标点、去重、置信度与警告
├─ SubtitleCueBuilder          原始分段 → 可排版 cue
├─ TranslationProvider         复用 M4
├─ SubtitleDocumentService     修订、编辑、缓存失效和导出
└─ DiagnosticRecorder          结构化指标和错误
                    │
HomePlayer.Core                公共契约，不引用 AI/Data/App
HomePlayer.Data                文档、修订、任务和设置持久化
HomePlayer.Ffmpeg              可取消的音频提取与标准化
HomePlayer.Playback            只消费既有字幕契约，不依赖 AI
```

依赖方向必须保持为 `App → AI → Core`，`Data` 实现存储接口，`Ffmpeg` 提供媒体基础能力。`Core` 不得引入模型运行时，`Playback` 不得引用 AI 项目。

### 9.2 Provider 抽象

Provider 不是简单一个 `Recognize(file)` 大函数，至少要声明：

```text
稳定 ProviderId / 版本 / 本地或云端
支持语言与自动检测能力
所需模型和运行时
CPU/GPU/内存/显存需求
段级或词级时间戳能力
标点、ITN、VAD、说话人能力
最大分段长度与重叠要求
取消、暂停和检查点能力
隐私与网络需求
```

识别接口以标准化音频块和上下文为输入，输出结构化分段。UI 不直接调用 ONNX、原生 DLL 或云端 SDK。

### 9.3 核心请求契约

逻辑模型至少包含：

```csharp
SubtitleJobRequest
{
    Mode,                       // TranslateExisting / RecognizeAudio / RecognizeAndTranslate
    MediaId,
    SourceFingerprint,
    SourceSubtitleStableId?,    // 直接翻译时使用
    AudioTrackStableId?,        // ASR 时使用
    RangeStartTicks,
    RangeEndTicks,
    RecognitionLanguage?,       // null 表示自动
    ProviderId,
    ModelId,
    ModelVersion,
    DevicePreference,
    EnableWordTimestamps,
    FormattingProfileId,
    TranslationOptions?,        // 直接翻译或识别后翻译
    HotwordsVersion?,
    CloudConsentId?             // 仅云端
}
```

`Mode` 决定必填字段和预检项：直接翻译不要求音轨，纯识别不要求翻译模型。任何影响输出语义的字段都必须进入参数指纹；UI 显示名称、导出路径和任务优先级不属于识别缓存键。

### 9.4 两条处理管线

```text
已有文本字幕直接翻译：
Probe / Validate
→ SourceFingerprint + SourceSubtitleStableId
→ 提取文本 cue，保留原时间和稳定 ID
→ 清理仅供模型阅读的样式与重复文本
→ TranslationProvider（有界上下文 + 结构化 ID）
→ 校验逐项映射
→ Translated SubtitleDocument Revision
→ 编辑器 / 播放器 / 导出器

无文本字幕语音识别：
Probe / Validate
→ SourceFingerprint + AudioTrackStableId
→ Audio Chunk Reader（带源时间戳）
→ VAD / Segment Planner
→ ASR Provider
→ RawTranscriptSegment
→ 去重 / 标点 / ITN / 质量警告
→ SubtitleCueBuilder
→ Original SubtitleDocument Revision
→ 可选进入上述翻译管线
```

每个阶段有独立输入输出、取消和资源上限。不得用一个不可拆分的后台方法同时承担读取、推理、排版、数据库和 UI 更新。

### 9.5 Windows 本地运行方案

本地识别和本地翻译均可作为正式能力，不依赖云端。首次下载模型后，媒体识别和文本翻译可以断网执行。

| 用途 | 候选方案 | 优点 | 集成注意点 |
|---|---|---|---|
| 多语言 ASR 首选评估 | `whisper.cpp` + 多语言 Whisper GGML 模型 | C/C++、支持 Windows、CPU、CUDA/Vulkan 等后端，可离线运行，容易做成私有原生依赖 | 必须使用多语言模型而非 `.en`；VAD、词级时间戳、取消和不同语言质量需实测 |
| ASR 对照方案 | `faster-whisper` / CTranslate2 | CPU/GPU、量化、VAD 和词级时间戳能力较完整 | 默认 Python 封装带来运行时打包和依赖管理成本，不应仅为原型方便直接定为正式方案 |
| 多语言上下文翻译 | `llama.cpp` + 经过评测的多语言指令模型 GGUF | 本地运行、C/C++、量化、CPU/GPU 后端，便于利用上下文、术语和风格指令 | 模型较大；必须约束结构化输出、逐项 ID、重试和上下文长度，不能让模型自由重排字幕 |
| 专用机器翻译 | NLLB-200 等多语翻译模型，经 CTranslate2/ONNX 等本地运行时集成 | 面向翻译任务、语言覆盖广，可作为低资源或稳定结构化方案评估 | 分词器和运行时依赖较多；上下文、口语、术语及各语言方向质量需实测，许可证单独审查 |

**推荐的首个工程组合：**优先验证 `whisper.cpp` 负责本地多语言识别，同时对比“本地多语言 LLM”和“专用翻译模型”两条翻译路线。二者都可离线，选择依据是 HomePlayer 的真实字幕测试集，而不是模型热度。

**推荐的产品分层：**

- 快速档：较小或量化模型，适合 CPU/低配置，明确较低质量预期。
- 平衡档：默认推荐，在质量、模型大小和速度之间折中。
- 高质量档：更大模型，面向有足够内存/显存的设备。
- 自动设备选择：先验证 CPU 可用基线，再按实测开放 NVIDIA CUDA 和跨厂商 Vulkan 等 GPU 路径；失败回退必须可见。

**集成原则：**

- 正式应用优先评估无需用户安装 Python 的原生运行方案；Ollama 等可用于开发验证，但不应成为普通用户的必需前置安装。
- 模型按需下载，不塞入基础安装包；量化只代表资源降低，不代表质量不变。
- 本地 LLM 翻译必须采用结构化协议、有限上下文和结果校验，不能执行字幕文本中的指令。
- 不在未实测前承诺某档模型在所有 CPU/GPU 上都能流畅运行。

官方技术资料：

- whisper.cpp：https://github.com/ggml-org/whisper.cpp
- faster-whisper：https://github.com/SYSTRAN/faster-whisper
- llama.cpp：https://github.com/ggml-org/llama.cpp
- NLLB-200 模型示例：https://huggingface.co/facebook/nllb-200-distilled-600M

### 9.6 任务状态与操作

沿用 M1 状态：

```text
Queued → Running → Completed
                 → Failed
                 → Cancelled
Paused / WaitingForModel / WaitingForResources
```

另行记录 `CurrentStage`：

```text
Validating / DownloadingModel / ReadingSubtitles / ExtractingAudio /
DetectingLanguage / Recognizing / Formatting /
Translating / Saving / Exporting
```

规则：

- 状态迁移持久化，迟到回调按 `JobId + OperationId + SegmentGeneration` 丢弃。
- 取消和暂停必须幂等；取消后重试创建新操作代际，不复活旧回调。
- ASR 进度优先按已处理音频时长计算；直接翻译按已确认 cue 数或文本工作量计算；模型下载单独显示。
- 预计剩余时间只能在样本足够后显示为估计，不保证固定速度。
- 已完成分段的校验包括输入指纹、参数指纹、模型版本、范围、结果完整性和校验和。
- 失败重试默认有界并可手工触发，不能无限自动重试耗电或产生云端费用。

## 10. 数据与文件设计

### 10.1 逻辑实体

不预先限定最终 SQL 字段名，但至少需要以下实体：

| 实体 | 关键内容 |
|---|---|
| `SubtitleDocument` | DocumentId、MediaId、源指纹、音轨 StableId、语言、文档类型、当前修订、创建/更新时间 |
| `SubtitleRevision` | RevisionId、父修订、原因、模型/参数指纹、格式 Profile、创建时间 |
| `SubtitleCueRecord` | 稳定 CueId、RevisionId、Start/End、原文、译文、说话人、置信度、警告、排序键 |
| `RawTranscriptSegment` | SegmentId、源范围、原始文本、词时间、语言、Provider/Model、结果校验和 |
| `CueSegmentLink` | CueId 与一个或多个 SegmentId 的映射 |
| `AiTask` | 通用任务状态、当前阶段、进度、错误、重试和资源等待原因 |
| `AiTaskSegment` | 任务分段范围、状态、尝试次数、检查点、输出引用 |
| `Glossary/HotwordSet` | 影片级、剧集级词汇与版本，供识别和翻译共享 |

所有时间使用整数 ticks 或明确的整数 TimeBase，不以浮点秒作为数据库主键或唯一时间依据。

### 10.2 源、字幕与音轨身份

媒体源指纹不能只使用文件路径，也不能默认依赖完整大文件 SHA-256。建议组合：

```text
MediaId（如有）
+ 规范化路径（用于定位，不单独作为内容身份）
+ 文件大小、mtime、时长和容器信息
+ 有界头部/中部/尾部内容采样哈希
+ ASR 时：所选音轨 StableId、编码参数和必要 extradata 指纹
```

直接翻译还必须记录字幕来源身份：

- 外挂字幕：规范化路径、大小、mtime 和完整文件内容哈希；文本通常较小，可直接计算完整哈希。
- 内嵌文本字幕：字幕 StableId、编码、实际提取文本与 cue 时间轴哈希。
- AI 识别字幕：原文档 ID、原修订 ID 和 cue 内容哈希。
- 直接翻译的 `TranslationCacheKey` 使用上述字幕源身份，不要求音轨指纹。

任务完成前再次检查媒体和直接输入字幕是否变化；如变化则禁止把结果绑定到新源。对网络媒体可限制采样读取预算，无法确认时提示“源身份置信度有限”，不能无提示复用旧结果。

### 10.3 缓存键与失效

```text
RecognitionCacheKey =
    SourceFingerprint
  + AudioTrackStableId
  + SelectedRange
  + ProviderId / ModelId / ModelVersion
  + RecognitionParameters
  + HotwordSetVersion

FormattingCacheKey =
    RawTranscriptRevision
  + FormattingProfileVersion

TranslationCacheKey =
    SourceCueRevision
  + TargetLanguage
  + TranslationProvider / ModelVersion
  + Style
  + GlossaryVersion
```

失效规则：

- 仅调整字幕行长、最大时长等排版参数：复用识别，只重建 cue。
- 修改术语表：翻译按影响范围失效；识别热词是否重算由实际热词内容决定。
- 更换 ASR 模型：原识别缓存不可冒充新模型结果，可保留为旧修订。
- 用户编辑：形成新修订，不因缓存清理而丢失。
- 源文件或音轨变化：旧文档保留供用户查看/导出，但标记不匹配，不自动启用。

### 10.4 存储位置和备份

- 文档、修订、人工编辑和任务元数据存入应用数据库。
- 模型、音频块、推理临时数据位于 AI 缓存目录，可安全清理。
- 供播放加载的 SRT/JSON 位于应用管理的字幕产物目录，路径由文档服务管理。
- 用户确认的人工编辑纳入备份；原始识别结果可选择备份，默认视为可重建数据。
- 删除缓存不得删除人工修订；数据库迁移前沿用现有备份机制。

## 11. 质量、性能与可靠性要求

### 11.1 字幕正确性硬门槛

无论模型质量如何，以下必须 100% 满足：

- 导出 cue 时间有效、排序稳定，无负时长、NaN 或空文本。
- 每条 AI cue 可追溯至模型和原始分段；人工新增 cue 标记为用户来源。
- 取消、恢复、重试和重启不会产生重复 cue 或跨文件混入。
- 排版重跑不改变原始转写；人工编辑不被自动任务覆盖。
- 失败范围有明确缺口或警告，不用空白静默掩盖。

### 11.2 多语言识别与翻译质量评估

建立版本化测试集，至少覆盖：

- 中文普通话、英语、日语、韩语、葡萄牙语、西班牙语、法语、德语、俄语、意大利语，以及每种后续宣称支持的语言；
- 清晰对白、多人交叉、口音、低音量、背景音乐和噪声；
- 电影、剧集、动画、纪录片和新闻；
- 数字、日期、单位、人名、片名和专有名词；
- 长静默、歌曲、无对白片头、片尾和极短语句；
- 不同采样率、声道布局、AAC/AC-3/EAC-3/FLAC/Opus 等输入；
- 已有字幕直接翻译中的长句、跨 cue 指代、重复行、样式标签、歌曲和上下文省略。

识别指标：

- 中文和日语使用 CER；空格分词语言使用 WER；韩语等语言必须声明分词器和采用 CER/WER 的具体口径，同时报告样本量和音频时长。
- 报告分段时间边界误差、漏识别区间、重复率和疑似幻觉率。
- 单独统计专有名词和术语，不用整体平均分掩盖关键错误。
- 低置信度标记需要评估召回/误报，不能把模型分数直接称为“正确概率”。
- 每个正式模型按语言、硬件和内容类型公布实测边界。

翻译指标：

- 按每个源语言—目标语言方向评估语义完整性、流畅度、术语一致性、错译/漏译/增译和双语映射正确率。
- 自动指标只能辅助，不能替代真实字幕样本的人工评审；特别检查日中韩敬语/语气、葡萄牙语等地区变体和多语专有名词。
- 原 cue 数、CueId 和时间轴必须完整映射；语言质量再高，只要错位或漏项就必须判为任务失败或带明确警告。

S0 选型完成后按语言分别冻结发布阈值，不能只验证中英文后把其他语言直接标成正式支持。未达到阈值的语种可缩小支持矩阵或标为实验；任何阈值都不能外推到噪声、歌曲、方言和所有口音。

### 11.3 性能与资源

- 不读取整部影片到内存；内存由模型预算和有界音频/结果队列控制。
- 默认播放时暂停，确保普通播放首帧、seek、音画同步和渲染无回归。
- 允许后台处理时，分别测量首帧增量、seek P95/P99、丢帧、CPU/GPU/显存和磁盘占用。
- 识别速度使用 RTF（处理耗时/音频时长）或实时倍速，必须附硬件、模型、语言和是否含下载。
- 10,000 cue 文档常用 UI 操作目标 P95 < 100 ms，不含用户主动视频 seek 的媒体解码时间。
- 取消请求应在 2 秒内被任务层确认；原生调用须在约定超时内退出。不能安全取消时进入隔离/失败状态，不提前释放仍被使用的资源。
- 长任务不得出现句柄、内存、显存或临时文件持续正向增长。

不在选型前承诺“2 小时电影必须 N 分钟完成”。每个硬件 Profile 使用真实媒体给出独立数据。

### 11.4 可靠性场景

必须覆盖：

- 模型未下载、下载中断、哈希错误、版本不兼容和磁盘不足。
- 文件离线、SMB 中断、处理中移动/替换、音轨损坏。
- GPU 不可用、推理崩溃、设备重置和自动回退 CPU 的显式策略。
- 暂停中退出、识别中强制结束进程、数据库写失败和临时文件残留。
- 同一文件重复提交、不同参数并行提交和批量任务乱序完成。
- 编辑器未保存时任务完成、局部重做与人工修改冲突。
- 已完成产物被用户手工删除或损坏后的重新生成。

## 12. 错误与用户反馈

错误包含稳定 `ReasonCode`、用户可读说明、是否可重试和诊断详情，不直接展示原生堆栈。

| 场景 | 用户行为与反馈 |
|---|---|
| 无音轨 | 禁止开始，说明文件不含可识别音频 |
| 模型未安装 | 提供下载，显示大小和位置；下载失败不影响原播放 |
| 磁盘不足 | 显示所需/可用空间，允许更改目录或清理缓存 |
| 语言检测不确定 | 展示候选，要求确认或允许按当前结果继续 |
| 某分段失败 | 保留其他结果，标记时间范围，提供仅重试失败段 |
| 源文件变化 | 停止提交旧结果，保留旧修订，要求重新确认 |
| 云端未授权/额度不足 | 不上传或立即停止后续上传，保留本地已有结果 |
| 输出路线不支持叠层 | 允许生成和导出，明确播放预览限制 |
| 保存失败 | 保留编辑缓冲，提供重试和导出紧急副本 |
| 用户取消 | 状态为 Cancelled，已完成结果可保留，不伪装为完整成功 |

进度提示应区分“正在下载模型”“正在识别 35%”“正在整理字幕”“等待播放结束”，而不是长期只显示旋转动画。

## 13. 隐私、安全与许可证

### 13.1 本地优先

- P0 的识别和翻译均默认在本地运行；模型下载与媒体/字幕处理网络行为分开说明。
- 不将完整媒体路径、音频内容、原文、译文、识别文本、热词或 API Key 写入普通日志。
- 诊断包默认只包含模型 ID、版本、错误码、阶段耗时和资源指标；文本样本需用户单独选择加入。

### 13.2 云端授权

每个云端任务开始前展示：Provider、发送的数据类型、时间范围、预计音频时长、是否包含术语/上下文和费用信息（可获得时）。

- 默认只发送所选音轨的必要音频分段，不上传完整视频。
- 授权只作用于约定范围，不自动扩展到后续任务或其他文件。
- 密钥使用操作系统保护的秘密存储，不进入字幕 JSON、数据库普通字段或诊断包。
- 网络失败、超时和取消必须停止后续分段上传；已发送数据的云端保留策略以 Provider 说明为准，不作虚假承诺。

### 13.3 内容与供应链安全

- 文件名、媒体元数据、识别文本、字幕和术语均只作为数据，不能触发 SQL、脚本、工具或文件操作。
- 云端返回和模型输出按不可信文本处理，导出时避免公式注入等附加风险；JSON/CSV 类诊断导出需要转义。
- 模型及原生运行时进入哈希校验、SBOM、许可证和私有依赖检查。
- 正式引入每个模型前审查模型权重、运行时和分词器许可证，不能把“可下载”视为“可再分发”。
- 不执行模型包内脚本；如运行时需原生代码，必须来自官方审核依赖包。

## 14. 诊断与可观测性

每个任务记录：

```text
JobId / OperationId / DocumentId / RevisionId
SourceFingerprint 摘要 / AudioTrackStableId 摘要
Provider / Model / Runtime / Device / OS
处理范围 / 各阶段耗时 / 已处理音频时长 / RTF
分段成功、重试、失败、取消数量
VAD 时长占比 / 原始文本长度 / cue 数量
质量警告类型与数量
CPU、内存、GPU、显存、磁盘和临时文件趋势
```

结构化事件至少包括：

```text
JobCreated / PreflightFailed / ModelReady / SourceChanged
AudioChunkStarted / AudioChunkCompleted
SegmentStarted / SegmentRecognized / SegmentRetried / SegmentFailed
CheckpointSaved / JobPaused / JobResumed / JobCancelled
FormattingCompleted / TranslationCompleted / ExportCompleted
```

不得用 `0` 代替无法观测的 GPU 时间或置信度；无法观测时为 `Unknown`。诊断文本遵循现有 URL/UNC 凭据和敏感参数脱敏规则。

## 15. 测试与验收

### 15.1 自动化测试

**纯逻辑单元测试：**

- 音频块到媒体时间的映射、重采样边界和 EOF。
- 分段重叠去重、重复文本检测和缺失范围标记。
- cue 拆分、合并、行长、时长、间隔、排序和 CJK/拉丁 Profile。

- 状态迁移、幂等取消、旧 OperationId 丢弃和断点恢复。
- SRT/VTT/JSON 导出往返、特殊字符、多行和超长片。
- 编辑器撤销/重做、批量替换、人工修改保护。

**集成测试：**

- 使用小型合成音频和受控假 Provider 验证完整任务链，不在单元测试中下载大模型。
- 使用真实 FFmpeg 样本验证多音轨选择、解码失败、SMB 超时和取消。
- 数据库升级、备份恢复、崩溃后的检查点与孤立产物清理。
- 模型清单篡改、哈希不匹配、原生运行时缺失和许可证清单检查。

**模型质量测试：**

- 固定测试集、模型文件哈希、运行参数和解码配置。
- 保存 CER/WER、时间边界和幻觉指标，模型升级必须做同集对照。
- 失败和无法观测样本不得从统计中静默删除。

### 15.2 P0 端到端验收

至少执行以下真实场景：

1. 对含日文字幕的视频选择“翻译已有字幕”，在未安装 ASR 模型、无可用音轨的情况下仍能完成本地中文翻译，且 cue 时间轴与原字幕一致。
2. 分别用外挂和内嵌文本字幕执行直接翻译，原文件不修改，仅译文和双语结果可播放、可导出。
3. 对中文普通话、英语、日语、韩语、葡萄牙语及其他首发语种逐项运行识别/翻译测试集，确认界面支持状态与实际质量报告一致。
4. 对 20 分钟以上、无字幕且含多音轨的视频选择指定音轨，完成本地识别并生成 SRT。
5. 处理中暂停、继续、取消，再新建任务；最终 cue 不重复、不串文件。
6. 识别或翻译中关闭并重启应用，已保存分段复用，未完成范围可继续。
7. 修改一句文本、拆分一句、合并两句、调整时间、撤销和重做，重启后结果一致。
8. 从编辑器逐句跳转和试听，启用字幕后进行播放、暂停、连续 seek、倍速和切集。
9. 导出 SRT、WebVTT 和 JSON，再由现有字幕解析器加载，文本和时间一致。
10. 对已有外挂字幕的文件生成 ASR 字幕，必须经用户主动切换路径，确认原文件不被覆盖且可自由切换。
11. 注入识别分段失败或翻译缺项/错位，确认成功范围可保留、失败范围可见且能单独重试，不产生错误映射。
12. 模型损坏、磁盘不足、文件离线和源文件/源字幕变化均进入明确状态。
13. 模型下载完成后断网，已有字幕翻译和音频识别仍可完成。
14. AI 关闭、模型缺失、识别失败和翻译失败情况下，原有播放与字幕行为无回归。

### 15.3 P1/P2 追加验收

- 批量任务中单项失败不影响其他项，报告数量准确。
- 原文局部修改只重译相关 cue，人工译文不丢失。
- 热词版本变化只失效必要范围，人名在整集/整剧中按术语表一致。
- 云端授权范围、取消上传和密钥脱敏经过验证。
- 边生成边预览时，迟到分段按代际提交，不造成 cue 抖动、旧字幕残留或播放时钟回归。

每个阶段均须：

## 16. 分阶段实施建议

### S0：样本、模型与运行时选型

- 冻结 P0 两条路径、首发多语言矩阵和识别/翻译测试集。
- 对比候选 ASR 模型在目标 CPU/GPU 上按语言统计的 CER/WER、时间戳、RTF、内存和许可证。
- 对比本地多语言 LLM 与专用翻译模型的语义质量、术语、结构化映射、速度、内存和许可证。
- 优先验证 `whisper.cpp` 及无需 Python 的本地集成，同时保留 `faster-whisper` 作为性能/质量对照。
- 验证最小原生/托管运行时、取消、长音频和模型包校验。
- 决定词级时间戳是正式能力还是仅部分 Provider 提供。

**出口：** 确定本地 ASR 与翻译 Provider、模型、硬件 Profile 和分语言质量阈值；不以“模型能输出一句话”作为通过。

### S1：AI 基础设施与输入链

- 完成 M1 所需模型、任务、缓存、配额和诊断能力。
- 实现文本字幕来源选择、内容指纹和原 cue 映射。
- 实现音轨稳定选择、独立音频提取、时间映射和有界分块。
- 建立文档、修订、原始分段、任务和检查点存储。

**出口：** 不接入真实模型也可通过假 Provider 验证直接翻译与 ASR 两类长任务、取消、恢复和数据库升级。

### S2：已有字幕本地直接翻译（M4A）

- 接入本地翻译 Provider、多语言源/目标选择和有界上下文。
- 保留原 cue 时间轴，校验结构化 ID，支持仅译文和双语结果。
- 提供基础预览、导出和失败段重试，不要求安装 ASR 模型。

**出口：** 已有文本字幕可在断网状态下完成本地翻译，原字幕不受影响，所有译文逐项映射正确。

### S3：多语言识别草稿与自动排版（M4B）

- 接入本地多语言 ASR、语言检测、VAD、去重、标点和质量警告。
- 实现原始转写保存和独立 `SubtitleCueBuilder`。
- 识别结果可进入 S2 的同一翻译链。

**出口：** 对真实长片按首发语种生成结构正确的完整草稿，所有失败范围可解释。

### S4：编辑、播放与导出（P0 发布候选）

- 完成虚拟化编辑器、试听、撤销、自动保存和质量导航。
- 接入 `SubtitleSession`、每文件偏好和现有字幕呈现。
- 完成 SRT/VTT/TXT/JSON 导出、备份和产物生命周期。
- 完成多语言质量、性能、长稳、离线、隐私和端到端验收。

**出口：** 用户既能直接翻译已有字幕，也能从无字幕文件得到可校对、可播放、可导出的字幕，稳定路径无回归。

### S5：术语、局部重做与批量（P1）

- 加入影片级/剧集级术语表、识别热词、局部重识别和局部重译。
- 加入批量任务和按季处理。
- 按实际需求增加云端 Provider 和说话人区分，二者不互相绑定，也不替代本地能力。

### S6：增量预览与下游复用（P2）

- 在稳定预生成基础上实现边生成边预览，不直接承诺完全实时。
- 将识别文本接入台词搜索、摘要、场景定位和无字幕配音。
- 每个下游能力单独定义质量门禁，不把 ASR 完成等同于配音可用。

## 17. 评审用默认决策

除非评审另有决定，实施按以下默认值推进：

1. **已有文本字幕直接翻译优先**，不强制 ASR；无文本字幕时才默认进入识别路径。
2. **本地识别和本地翻译都是 P0 正式目标**，云端仅是后续按任务授权的可选扩展。
3. **多语言是首发需求**，至少实测中、英、日、韩、葡、西、法、德、俄、意，不以中英文结果替代其他语种验收。
4. **离线预生成优先**，首版不做完全实时识别。
5. **完整闭环优先于模型数量**，一个多语言模型也必须逐语言验证，不虚标支持状态。
6. **原始转写与 cue 分离，直接翻译保留原时间轴**，排版变化不重跑模型。
7. **独立读取音频**，不侵入主播放音频管线和时钟。
8. **应用管理产物，用户显式导出**，不默认在视频旁写文件。
9. **人工编辑是用户数据**，缓存清理、重试和模型升级均不得覆盖。
10. **播放时让路**，默认播放期间暂停后台识别和翻译。
11. **先单文件后批量，先段级可信时间后扩展词级能力**，不虚标模型能力。

## 18. 待评审决策

以下事项不阻碍需求评审，但进入 S0/S1 前需要形成结论：

| 决策 | 推荐方向 | 影响 |
|---|---|---|
| 首个 ASR 模型与运行时 | 优先实测 whisper.cpp 多语言模型，由 S0 同集质量、RTF、取消和许可证实测决定 | 原生依赖、安装包、硬件矩阵 |
| 首个翻译模型与运行时 | 对比本地多语言 LLM（llama.cpp/GGUF）与 NLLB 等专用翻译模型 | 上下文质量、结构化映射、模型大小和速度 |
| P0 正式语言 | 中、英、日、韩、葡、西、法、德、俄、意逐项实测，通过何种语言就正式开放何种语言 | 测试集、质量承诺、UI 文案 |
| GPU 后端 | 先建立 CPU 可用基线，再按实测开放 CUDA/Vulkan 等 GPU 路径 | 显存、驱动、回退和分发 |
| 词级时间戳 | 有原生能力则启用，无能力则明确估算 | 拆分精度和编辑器提示 |
| 云端 Provider | P1 再接入，不预设某一家服务，本地功能不依赖它 | 授权、费用、隐私和密钥存储 |
| 说话人区分 | P1 可选，不作为识别成功前置条件 | 模型资源、质量和导出格式 |
| 自动启用生成字幕 | 每次任务可选，默认不覆盖后来发生的手动选择 | 播放偏好与竞态处理 |
| 批量入口 | P1 开放多选和当前季，不开放默认全库 | 资源、费用和任务规模 |

## 19. 最终交付定义

“AI 自动字幕完成”不等于“接入了一个语音识别模型”。P0 只有同时满足以下条件才算完成：

- 已有文本字幕能够直接本地翻译，不强制语音识别，且原 cue 时间轴保持不变。
- 无文本字幕时能够使用本地多语言模型识别，并可进入同一翻译、编辑和导出链。
- 首发语言按语种实测并如实展示，日语、韩语、葡萄牙语等不被中英文质量结果替代。
- 识别和翻译在模型下载后均可断网运行，云端不是必需条件。
- 模型可获取、可校验、可删除，能力状态真实。
- 字幕源、音轨、语言、范围和隐私选择明确。
- 长任务可取消、恢复和诊断，资源使用有界。
- 识别与翻译结果具有可信来源映射和结构正确的时间轴。
- 用户能校对、试听、撤销、保存和局部修复。
- 字幕能在支持的播放路线中使用并正确回退。
- 产物可导出、可备份，人工修改不会被覆盖。
- 真实媒体质量、性能、异常和无 AI 回归均完成验收。

## 20. 当前测试版实现范围

本次首先实现一个可试用版本，不代表上述完整 P0 已全部验收：

- 播放页“字幕 → AI 自动字幕 / 翻译”提供独立窗口。
- 检测到已有外挂或内嵌文本字幕时默认直接翻译，保留原 cue 时间轴，不要求音轨或 ASR 模型。
- 无文本字幕时可通过 `whisper.cpp` 多语言模型和 Silero VAD 识别，也可选择 Sherpa-ONNX SenseVoice；英语/日语/韩语默认可使用 Sherpa，其他语种可手动切换 Whisper。
- 模型已安装且没有可用文本字幕时，可在打开视频后自动开始 Sherpa 实时字幕；音频由独立 FFmpeg 进程提取，使用 10 秒窗口、8 秒步进和 2 秒重叠，低能量静音块跳过。跨块文本按规范化后缀/前缀去重，最终 cue 按句子、词边界、行长和时间重新排版，不再直接显示原始块。手动选择其他字幕、seek 或切集会隔离旧任务。
- Sherpa CUDA 已使用官方英语、日语、韩语样本及连续混合样本实测；约 19 秒连续样本约 5 秒完成，并已在真实视频打开流程中自动生成完整三语 SRT。优化后 41 秒连续长句样本生成 7 条无重叠 cue，约 7.9 秒完成，并通过实时播放与完整导出验证。
- 本地翻译使用 Qwen3 GGUF 模型和 `llama.cpp`，支持仅译文、双语和识别后翻译。
- 模型从 HF-Mirror 或 Hugging Face 按需下载，支持断点续传、文件大小和 SHA-256 校验；运行时使用固定版本并纳入 SBOM。
- 提供任务进度、取消、逐条文本校对、保存修改、SRT/VTT/TXT/JSON 导出和当前影片启用。
- 支持 Windows x64 CPU 与 NVIDIA CUDA 12；提供自动、CUDA、CPU 选项，自动模式下 GPU 启动失败可回退 CPU。
- RTX 3090 实测：Whisper Small 热启动 10 秒样本识别约 2.28 秒（CPU 约 8.17 秒）；Qwen3 4B 的 8 条/两批次翻译约 35.8 秒（CPU 同场景约 405 秒）。首次 CUDA 初始化/JIT 可能明显增加首次耗时。

当前测试版尚未完成完整 P0 中的任务数据库、应用重启后的识别续作、批量/按季、试听与撤销栈、局部重做、模型质量门禁和全语言正式认证。这些能力继续按 S1–S6 推进，不在界面上宣称已经支持。
